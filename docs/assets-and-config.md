## 一、保姆级使用说明书（重点）

### 1.1 它的定位

> 这个文件是一份「**写给 AI 看的工作指令书**」，专业名字叫系统提示词（Master Command，总控命令）。它本来的读者就是 AI、不是人——**所以你读不懂、看着一堆符号发懵，非常正常，完全不是你的问题。**

**这句话值得注意**：v9.0 本来就是个 agent prompt，不是给人看的。说明书是把 prompt 翻译给人的桥。

**打比方（原文）**：

> 它像一台全自动洗衣机：剧本是脏衣服，第一页的参数是洗衣程序，你按下启动，它自动洗完；你只管最后「晾衣服」。
>
> 又像你临时外包了一个五人剧组：总编剧负责整理剧本，分镜导演负责拆镜头，美术总监负责定风格和人物场景图，模型翻译负责适配不同 AI 工具，质检负责逐镜把关。**你是甲方，只负责提需求和验收。**

### 1.2 五块产物（说明书 §0.2）

| # | 产物 | 大白话 | 拿去干嘛 |
|---|---|---|---|
| 1 | **全片总控** | 整片风格、段落总表、情绪起伏曲线 | 确认方向，相当于「施工蓝图」 |
| 2 | **图片素材提示词** | 人物定妆/多视图、场景锚定图、道具板 | 复制到画图工具出素材图 |
| 3 | **分镜视频提示词** | 每个镜头一段、模型「看得懂」的指令 | 复制到视频工具逐段生成 |
| 4 | **声音/音乐/转场说明** | 配音、配乐、剪辑衔接的指引 | 交给后期 |
| 5 | **质量审计报告** | 逐镜体检、风险打分、因果检查 | 确认没问题，有问题让它修 |

### 1.3 明确划的边界（§0.3）——产品预期管理

> **它本身不生成图片、不生成视频。** 它产出的是「提示词」，真正出图出视频要靠别的工具。
>
> **它不会替你编剧情、改结局。** 这是故意设计的，目的是防止 AI 乱加戏、毁掉你的故事；**剧情事实只认你给的原文**。
>
> **它不能代替你做审美判断。** 整片的风格方向需要你点头确认，它负责把你确认的方向稳定地执行出来。

**第三条最老实**：把「审美」划给用户，「执行」留给自己。这是我们产品该学的态度。

### 1.4 三步流程（§2）

```
第 1 步  把命令全文「装进」AI（新对话第一条）
   ▼
第 2 步  发剧本 + 一句「启动话术」（第二条）
   ▼
第 3 步  看【运行配置】、回答【待确认清单】，说「确认交付」
   ▼
拿到 5 块产物 → 先出素材图 → 再逐段生视频 → 后期合成
```

**关键设计：命令先发、剧本后发。** 让 AI 先「进入角色」，再读剧本。

**三种装载方式**（A 复制粘贴 / B 系统提示词框 / C 上传文件），每种都给了现成话术。

**三套启动模板**：

| 模板 | 适用 | 内容要点 |
|---|---|---|
| **1 全自动** | 第一次最推荐 | 全部默认/AUTO；先出【运行配置】+【待确认清单】，等确认再全量交付 |
| **2 我有明确要求** | 已经清楚要什么 | 直接给 D、模型、画幅、字幕/BGM 四条 |
| **3 先看计划** | 剧本长、怕理解跑偏 | **只要运行配置 + 规范事实台账 + 待确认清单**，暂不出分镜 |

**模板 3 最有参考价值**：它把「事实核对」和「出稿」分成两个回合，用户可以先把人物/场景/道具对不对准，再往下走。

### 1.5 配置面板逐行翻译（§3）

说明书把 v9.0 的 6 组变量全部翻成了人话。几个易错点：

**① 时长**

> **时长是最高杠杆** —— 改一个数，时间码、台词预算、动作槽、节拍、子镜切分全跟着变。

**② 目标模型**

模型选择表（按用途）：

| 我想做什么 | 画幅 | 视频模型 | 图片模型 |
|---|---|---|---|
| 抖音/快手/视频号竖屏短剧 | 9:16 | SEEDANCE_2.5 或 KLING | GPT_IMAGE |
| B站/YouTube 横屏电影感 | 16:9 | SEEDANCE_2.5 | GPT_IMAGE |
| 3D 国漫 / 动画感 | 16:9 | SEEDANCE_2.5 | COMFYUI_3DGUOMAN |
| 真人写实短片 | 16:9 | SEEDANCE_2.5 | GPT_IMAGE |
| 古风仙侠 / 水墨 | 16:9 或 2.35:1 | SEEDANCE_2.5 | GPT_IMAGE |
| 出海英文内容 | 横或竖 | KLING / RUNWAY | GPT_IMAGE |
| 完全拿不定主意 | 随便 | AUTO | GPT_IMAGE |

**新手原则**：完全不懂就全部保持 AUTO/默认，先跑通一次，再回来慢慢调。

**⑤ 声音 / 音乐 / 字幕 —— 最容易误会的一组**

| 变量 | 默认 | 含义 | 易错点 |
|---|---|---|---|
| `BGM_POLICY` | `POST` | 提示词里写「无配乐」，音乐留到剪辑后期 | **直接生成的视频没有背景音乐是正常的，不是出错** |
| `DIEGETIC_SOUND` | `ON` | 保留环境音、动作音、对白 | `OFF` 连环境音都不要 |
| `SUBTITLE` | `OFF` | 画面不出现字幕文字 | `ON` 反而降低出片成功率 |

**这三条是产品必须解释的** —— 用户第一反应一定是「怎么没声音/没字幕」。

**⑥ 镜头与连续性（进阶，第一次不用动）**

| 变量 | 取值 |
|---|---|
| `SHOT_SIZE_POLICY` | `STANDARD` 标准 ｜ `CINEMATIC` 更强景别层次 ｜ `VERTICAL_TIKTOK` 竖屏近景特写为主 |
| `MAX_FACES_VISIBLE` | 默认 3；群戏按「焦点纪律」处理 |
| `CONTINUITY_REBUILD` | `FROM_FACTS` —— **强制每镜头从事实重建站位，不要改** |
| `ONE_TAKE_PREFER` | `false` ｜ `true` 尽量一镜到底 |
| `VFX_GRADE` | `AUTO` / `S` / `A` / `B` / `NONE` |
| `NEGATIVE_PROMPT_LEVEL` | `CORE` 只给关键「不想要」｜ `FULL` 完整清单 |

### 1.8 速算表（§7.6）—— 可直接抄进代码

| 时长 D | 台词上限 / 建议（字） | 动作槽 | 节拍 |
|---|---|---|---|
| 5 秒 | 15 / 12 | 3 | 2 |
| 6 秒 | 18 / 15 | 4 | 2 |
| 8 秒 | 24 / 20 | 5 | 2 |
| 10 秒 | 30 / 25 | 6 | 3 |
| 12 秒 | 36 / 30 | 7 | 3 |
| 15 秒 | 45 / 37 | 9 | 4 |

> **只到 15 秒就停。** 原资料表里有 20 秒 / 30 秒两行，那是**其它模型**（Seedance 最长 30 秒）的档位。
> **H3 单镜硬上限 362 帧 ≈ 15.08 秒**（`secondsToFrames` 封顶），超过 15 秒的请求会被截断到 15.08 秒。
> 所以 **D 的合法区间是 5–15 整数秒**；要更长的戏，按公式 `k = ceil(D / 15)` 拆成多条，**不是拉长单镜**。

**四个公式**：

```
台词上限 ≈ floor(秒数 × 3)
台词建议 ≈ floor(秒数 × 2.5)
动作槽   ≈ min(9, round(秒数 × 0.6))
视觉节拍 ≈ ceil(秒数 ÷ 4)
超模型上限 → 切成 ceil(秒数 ÷ 上限) 个子镜
```

**取整方向要注意**：

- 台词两列**向下取整** —— 15×2.5 = 37.5 → **37**（不是 38）
- 动作槽**四舍五入**，再封顶 9
- 视觉节拍**向上取整** —— 5÷4 = 1.25 → **2**

**H3 单镜上限用 `Mmax = 15`**（362 帧 ≈ 15.08 秒）。超过就拆条，不是拉长。

### 1.9 黑话词典（§7.4）—— 产品文案的现成素材

| 黑话 | 大白话（原文） |
|---|---|
| Phase A / Phase B | 两个内部阶段：A 把剧本整理成事实清单；B 规划镜头并翻译成模型提示词 |
| **规范事实台账（CF）** | AI 内部唯一「事实清单」：世界观、场景、人物、道具，**每条都带来源** |
| **规范镜头计划（CSP）** | AI 内部唯一「镜头清单」：每镜景别、运镜、动作、台词等 |
| **适配器（Adapter）** | 把同一份内部计划翻译成不同模型格式的模块 |
| **单点定义** | 每个人物/场景/道具只在一处定义，别处只引用编号、不重复描述 |
| **从事实重建** | 每段开头按事实重算「第 0 秒站位」，不沿用上段画面，防止漂移 |
| **所见即所得（WYSIWYG）** | 提示词只写镜头里实际看得见、听得着的内容 |
| **9 槽预算** | 一个镜头最多约 9 个「动作事件」，数量由时长算出 |
| **时长级联** | 时长一改，时间码/台词/动作/节拍等自动连锁重算 |
| **锚点** | 状态变化的起点状态与终点状态，如变身前后 |
| **轴线 / 越轴** | 对话戏机位应保持在人物同一侧，越轴会让观众看晕 |
| **保留度 retention** | H3 中参考内容被保留的程度，如 `fully_preserved` |
| **质量门 / 门禁** | 必须通过才能进入下一步的检查点 |

> **这些「大白话」可以直接做我们 GUI 的 tooltip 文案。** 写得很准，不用重新编。

### 1.10 16 条排错 FAQ（§8）—— 产品错误提示的参考

每条按「现象 → 原因 → 直接复制发给 AI 的话」组织。**这个三段式结构本身值得学**：给了用户一句可执行的话，而不是只解释原因。

挑几条对我们有直接价值的：

| 现象 | 原因 | 说明 |
|---|---|---|
| 人物每个镜头长得都不一样 | 没挂角色参考图，或每段都重新描述了外貌 | → 用资产图唯一参考，**各段不再单独描述外貌** |
| 场景/道具前后不一致 | 没有以资产图为唯一参考 | → **不要在分镜里重新描述场景结构或道具形态** |
| 台词在规定时间里念不完 | 超过该镜台词预算 | → 拆成两个镜头，或精简台词，**并把时间码和后续镜头顺延重算** |
| 动作太多、一个镜头演不完 | 超过 9 槽动作预算 | → 保留关键动作、删并其余，或拆成两段，**然后重算时间码与下游** |
| 生成的视频没有背景音乐 | `BGM=POST` 默认如此 | **属于正常，无需改** |
| 视频里没有字幕 | `SUBTITLE=OFF` 默认如此 | 正常，需要才改 ON |
| 我改了参数但结果没变 | 没有触发级联重算 | → **请严格按级联公式重算全部产物，不只是改时间码尾数** |
| MiniMax 报「环绕运镜」/ 人物太小 | 该模型禁环绕、人物不入远景 | → 拆成 `truck` + `pan`，**调整到全景以内** |
| 出图比例不对 / 比例写进正文 | `wh_ratio` 用法错误 | → **把比例从描述正文删除，只在 `wh_ratio` 字段填写** |
| 图里出现多余文字 / 手指畸形 / 多视图不像同一人 | 负向词不全 | → 加「无文字、无水印、肢体畸形、多余手指」 |
| 想只重做某一镜 | 重做也必须从事实重建 | → **从规范事实重建该段初始位置**，修改后重跑受影响的下游与审计 |

**注意最后一条**：**只重做一镜也要从事实重建，不能只改那一镜**。这是 R3 的延伸。

### 1.11 三句「救命话术」（附录 A）

> 1. 我已改第一页，请按级联公式重算全部产物。
> 2. 审计第 X 项为 2 分，请定位修复并重跑受影响下游。
> 3. 待确认项先按你的补全值出片，保留【待确认】标记。

**第 3 句很有用**：允许用户跳过待确认项，但**必须保留标记**。这比强迫用户答完所有问题体验好。

### 1.12 毕业标准（§9）

> □ 不看教程也能完成「发命令 → 发剧本 → 确认 → 拿产物」
> □ 能说清 5 块产物各自复制到哪里
> □ 会改时长和画幅，并知道要让 AI 重算
> □ 会挂参考图、逐段生成视频
> □ 审计出现 2 分项时会让它修复
> □ **知道「无配乐、无字幕」是默认设置，而不是故障**

**最后一条本鲸觉得最重要**：它把「用户误解」当成一等公民来处理。

## 二、H3 素材准备清单（prepare-checklist.md）

### 2.1 设计原则

> 给用户看的「出词前要准备什么」。**按分支分别列出，只给用户当前那条分支的部分**，不要把几张表都塞过去。
>
> 每条都标明**必须 / 可选**；用户缺了「必须」项就明确说缺了没法做，缺「可选」项照常出词。

**这两条是产品设计原则**：

1. **上下文相关** —— 只给当前分支的，不给全部
2. **可执行** —— 必须/可选分开，缺了会怎样说清楚

### 2.2 通用项（所有分支都要列）

**必须**

- 画面里所有人都是 18 岁以上（合规项，我们不一定要这条，看定位）
- 只用你有权使用的素材

**给图的分支（I2VA / Ref2VA / Hybrid）还要满足**

- 图片清晰、人物的脸看得清、少遮挡（脸部被大面积遮住、糊、过曝都会**影响人物绑定**）

**可选但建议**

- 画面内不要有水印、字幕、Logo、界面元素、可读文字（提示词末尾会声明排除，**但源头干净效果更稳**）
- 说明图里除主角外还有谁、那个人是什么角色（入镜互动 / 背景虚化 / 画外）

### 2.3 各分支的准备清单

> **按输入类型分四类讲**（文生 / 单首帧 / 多参考 / 混合），**实际有六种 `task_type`**：
> `i2va` 与 `l2va` 共用同一份清单（区别只在标首帧还是尾帧），`fl2va` 就是首帧清单再加一张尾帧，
> 这两种引擎会从素材构成自动推导，**不需要单独的清单**。
> `ref2va` 与 `hybrid` 的区别只有一条：**hybrid 多一张关键帧**。

**T2VA（文生视频）**

| 项 | 内容 |
|---|---|
| 必须 | **不需要任何图片或视频** —— 只给文字 |
| 必须 | 一段具体文字设定，至少说清：人物（年龄感/发型发色/瞳色/脸型气质/身材）、服装（款式/材质/颜色/配饰）、场景（室内外/空间/光线时段/时代感）、动作与落点 |
| 必须 | 目标时长：未指定按 **5 秒**；要改给 **5–15 的整数秒** |
| 说明 | **T2VA 里不要放音频** —— 壳里没有 `<Audio N>` 的位置 |

**两个代价**：

> - **没有图可锚定**：人物长相、服装、场景、画风全靠文字。**描述含糊 → 每次出来的都不一样。**
> - 如果你对人物外形有明确要求（要「就是这个人」），**别走 T2VA**。
> - 就算给了图片/视频，**T2VA 里一条都不会被采用**。

**I2VA（首帧图生）**

| 项 | 内容 |
|---|---|
| 必须 | **恰好一张图**，且它**就是**视频从 0.00 秒开始的那一帧 |
| 必须 | 目标时长同上 |

**两个后果**：

> - 这张图**同时锁定了人物、服装、场景、机位和画幅** —— 后面改不了，除非换图。
> - **给多张图不会浪费**：多给图会自动升级成 `hybrid`（首帧 + 参考）或 `ref2va`（纯参考），**两张都会被采用**。
>   只有你明确指定走 `i2va` 时，才会只取一张、其余忽略 —— 这种时候界面会提示你。

**Ref2VA（参考图生）**

| 项 | 内容 |
|---|---|
| 必须 | **至少一张**图。**一张纯人物图就够** —— 它提供身份与外观，**不会被当成视频首帧** |
| 可选 | 更多张图，每张说明它干什么用 |

**图的角色表**：

| 图的角色 | 举例 |
|---|---|
| 人物主体 | 这张的脸、发型、身材 |
| 服装 / 道具 | 这件衣服、这个项圈 |
| 场景 / 构图 | 这个房间、这个机位 |
| 动作 / 姿态 | 这个跪姿、这个角度 |
| 关键帧 | 这张当作第 3 秒的画面 |

> 不说明也行，会按画面实际内容自动判；**但两张图在同一职责上冲突时**（例如都当「场景」却是不同房间），会先来问你。

**Hybrid（关键帧 + 参考混合）**

| 项 | 内容 |
|---|---|
| 必须① | **一张关键帧**，明确指出它是 0.00 秒那一帧；想夹住结尾再加尾帧 |
| 必须② | **至少一份参考素材**（另有参考图/音/视频）。**只给关键帧、没有参考素材 → Hybrid 不成立** |

**编号会怎么排（表格很实用）**：

| 你给了 | 关键帧 | `<Picture N>` |
|---|---|---|
| 首帧 ＋ 参考图 | `first_frame`（独立标识行） | `<Picture 1>` = 参考图①、`<Picture 2>` = 参考图②… |
| 首帧 ＋ 尾帧 ＋ 参考图 | `first_frame` ＋ `last_frame`（各一行） | 同上 |
| 尾帧 ＋ 参考图 | `last_frame`（独立标识行） | 同上 |

> **关键帧用字段名 `first_frame` / `last_frame` 独立标识、不占 `<Picture N>` 号**；`<Picture N>` 全部留给参考图。

### 2.4 「所有分支都要告诉我的信息」（§末）

这段是**产品级的输入清单**，比前面那些分支细则更实用：

> - **要不要人物声线参考音频**（出词前会被问一次）
> - **要演什么**：动作链与转折，以及**结尾落在哪**
> - **台词**：原话、谁说的、用什么称呼（默认中文）
> - **要不要配乐**：默认没有（`non_diegetic_music` 写 `N/A`）
> - 有没有**想避开**的套路（避免重复用过的叙事装置）

### 2.5 参数不在提示词里设

> **时长、分辨率、画幅都不写进提示词正文**，而是在提交时设置。正文只用切点时间戳（`At 00:03.500, …`）和结尾落点来表达时长。

**这条我们已经知道了，但值得再强调一次** —— 参数走 job 请求，不走 prompt 文本。

## 三、人物／场景／时间线登记表（character-scene-sheet.md）

### 3.1 定位

空白模板。开新作品时复制到工作区 `<工作区>/故事/设定.md` 再填。

**硬性边界**：

> 技能目录是**只读模板库**。作品正文、角色设定、剧本内容、案例正文**一律只落工作区，不得写回技能目录**。这样多部作品各自独立，技能本身保持通用，**可随时复制或分享而不带出任何私人内容**。

**这条对我们有直接启发**：模板与作品数据要物理分离，模板可分享，数据留在本地。

### 3.2 六个章节的字段

**一、人物表**

| 角色 | 年龄 | 外形 | 关系 | 性格 | 设定来源 |
|---|---|---|---|---|---|
| … | | | | | |

**`设定来源` 列**（从人物图起手时**必填**，全程以此为准）：

| 值 | 含义 |
|---|---|
| `外形＝图片` | 外观锚定用户给的图，重锚时以图为准 |
| `设定＝用户指定` | 性格/背景/关系全部由用户给定，**后续不得自行补全或漂移** |
| `设定＝AI推·已确认` | 由图片反推的草案，用户已点头 |
| `设定＝AI推·待确认` | 草案，**用户点头前不得当作既定设定使用** |

**这一列是这套模板最有价值的设计** —— 它把我们文档里的「EVID 证据等级」落到了具体字段上，而且区分了「谁定的」。

**外形约束提醒**（逐条列出，写动作前自查）：

> - 例：`<某角色>` 是短发 → **禁用「手指插进头发」**，改扣后颈/按后脑勺/攥住衣领
> - 例：`<某角色>` 体型特殊 → 对应禁用哪些姿态与动作

**这个「负面约束」思路很实用**：正向描述「她长发」不管用，得明确禁止和长发冲突的动作。

**二、关系张力**

- 谁与谁的关系是什么，**何时、被谁、以什么方式知晓**
- 各角色对彼此的态度差异（**同一件事上各自立场不同才有戏**）

**三、场景清单（按时间线）**

| 序 | 场景 | 地点 | 关键点 |
|---|---|---|---|
| 1-15 | | | |

**四、空间设定**

- **核心通道**：哪两个空间之间的哪条路径**可反复使用**
- 各主要空间的位置关系与固定陈设（光线、家具、**可复用的锚点物**）

**「核心通道」是个巧思**：多个场景之间反复走的路径（走廊、楼梯、门），是空间连贯性的骨架。

**五、已用过的叙事装置（避免重复）**

> 逐条记录已用过的装置。转视频提示词时**不得回收复用**，除非用户点名复用。

**六、画风偏好**

- 默认画风
- 若另指定，写这里

## 四、三份合起来看：补上了什么

### 4.1 与前两份文档的关系

| 文档 | 覆盖 |
|---|---|
| [分镜系统规则.md](./storyboard-rules.md) | v9.0 **主命令**：铁律、级联、资产编号、适配器、质量门 |
| **本文档** | v9.0 **使用说明书** + 输入侧清单 + 设定表模板 |

**说明书补的是主命令没有的**：

| 主命令缺的 | 说明书补上了 |
|---|---|
| 怎么开始 | 三步流程 + 三套启动模板 |
| 五块产物怎么用 | 每块产物「拿去干嘛」 |
| 参数怎么调 | 逐行翻译 + 速查表 + 11 个配方 |
| 出错了怎么办 | 16 条 FAQ + 三句救命话术 |
| 术语看不懂 | 黑话词典（大白话对照） |
| 用户会误解什么 | 「无配乐无字幕是默认，不是故障」 |

### 4.2 三个对我们产品最有价值的设计

**① 上下文相关的输入清单**

> 只给用户**当前那条分支**的部分，不要把几张表都塞过去。

我们现在方案里是「一次性列出所有参数」，这个做法更好。

**② 按「我想要 X」组织参数，不按变量名**

`节奏更快 → D=6或8` 比 `GLOBAL_SEG_DURATION_SECONDS: 8` 好用一百倍。

**③ 明确区分「正常现象」和「故障」**

> 直接生成的视频没有背景音乐是正常的，不是出错。
> 视频里没有字幕是默认设置，而不是故障。

**这条能砍掉大量无效反馈。**

### 4.3 设定来源列 vs 证据等级

两个概念要对齐：

| 概念 | 出处 | 粒度 | 取值 |
|---|---|---|---|
| **EVID 证据等级** | v9.0 主命令 | 每条**事实** | `原文` / `推断` / `补全` / `待确认` |
| **设定来源** | 登记表模板 | 每个**角色** | `外形＝图片` / `用户指定` / `AI推·已确认` / `AI推·待确认` |

**两者不冲突，是不同粒度**：

- EVID 标「这条事实从哪来的」
- 设定来源标「这个人是谁定的」

**建议我们的数据模型两个都留**：`Asset`/`Character` 挂 `source`（设定来源），字段级挂 `evidence`（EVID）。

## 五、对本项目的适配判断

### 5.1 建议照搬

| 项 | 理由 |
|---|---|
| **五块产物的划分** | 我们的交付物应该也是这几块 |
| **三步流程 + 启动模板** | GUI 的向导流程可以直接照这个设计 |
| **上下文相关的输入清单** | 只给当前分支需要的东西 |
| **「我想要 X」参数组织** | GUI 参数面板的组织方式 |
| **11 个配方** | 一键预设，用户不用懂变量 |
| **速算表** | 直接进代码，注意取整方向 |
| **黑话词典** | 直接做 tooltip 文案 |
| **16 条 FAQ 的三段式** | 现象 → 原因 → 一句可执行的话 |
| **`设定来源` 列** | 落进 `Character.source` 字段 |
| **外形约束（负面约束）** | 正向描述不管用，得明确禁止冲突动作 |
| **核心通道** | 场景连贯性的骨架 |
| **已用装置记录** | 避免重复套路 |
| **明确区分正常现象与故障** | 减少无效反馈 |

### 5.2 需要改写

| 项 | 原资料 | 我们的做法 |
|---|---|---|
| 18 岁红线 | 通用项必须 | 我们的定位不同，**看产品边界再定**，但要有类似的可配置内容闸门 |
| 人物声线只收参考音频 | 上限三条、拒 BGM | 我们**不做这个限制**，音频用途放开 |
| `BGM_POLICY` 默认 `POST` | 视频内无 BGM | 我们是**本地拼装**，音频是单独一条轨，语义不同 —— 我们不需要「后期加」这个概念 |
| 模板/数据分离 | 技能目录只读 | 我们**改成「内置模板 + 用户数据目录」** |

### 5.3 待确认

1. **我们的「五块产物」怎么切** —— 是不是也分总控/素材/分镜/声音/审计？
2. **要不要做「配方」这种一键预设** —— 竖屏短剧、横屏电影、3D 国漫
3. **`设定来源` 要不要暴露给用户看** —— 它比 EVID 更易理解，可能是个好功能
