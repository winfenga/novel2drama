## 二、交付格式：已定（2026-11-10）

`对话决策记录.md` L215-216 记的那项，**现在定了**。

**定案：三个都给，不是一个。**

| 格式 | 解决什么 | 给谁 |
|---|---|---|
| **FCPXML** | 带音轨、带位置，直接导入就能剪 | FCP / DaVinci / 剪映专业版 |
| **SRT** | 字幕文本 + 时间戳 | 播放器、平台上传、校对 |
| **CSV** | 一行一镜的纯数据 | 脚本、Excel、排查 |

**完整规格见 [接口契约.md](./api-contract.md) §8.5**，含 XML 骨架、CSV 列定义、校验清单。

三条关键决定：
1. **时间轴一律全集绝对时间**，不是单镜相对时间
2. **音频不切碎**，整条铺满序列，作为独立 lane —— 切碎会有接缝
3. **有缺口就报错**（`delivery_incomplete`），不许留空占位

## 五、图片超分：重写并实测跑通（2026-11-10）

### 为什么重写

原 `单图超分.json`（从 ComfyUI 工作流压缩包里提出来的）**跑不了**：

| 工作流引用的模型 | 磁盘实际 |
|---|---|
| `seedvr2_3b_nvfp4.safetensors` | ❌ 不存在 |
| `seedvr2_ema_vae_fp16.safetensors` | ❌ 不存在（真名 `ema_vae_fp16`） |

根因不是写错名字，是**那条链用错了加载器**：它走 `UNETLoader` + `VAELoader`，这两个通用加载器只查 `models/unet`、`models/diffusion_models`、`models/vae`；而 SeedVR2 权重在 `models/SEEDVR2/`，由插件自己注册路径。**通用加载器根本看不见。**

### 重写成什么

改成 SeedVR2 **官方三件套**：

```
LoadImage → SeedVR2VideoUpscaler → SaveImage
                ↑            ↑
      SeedVR2LoadDiTModel  SeedVR2LoadVAEModel
```

文件在 `workflows/`：

| 文件 | 用途 |
|---|---|
| `image-seedvr2-upscale.api.json` | API 格式，程序提交用 |
| `image-seedvr2-upscale.ui.json` | 画布格式，拖进 ComfyUI 用 |

### 实测结果（真跑，不是推演）

| 场景 | 输入 → 输出 | 耗时 |
|---|---|---|
| `resolution=1080` | 1168×2016 → **1080×1864**（缩小了） | 41.6 s |
| `resolution=1440` | 1168×2016 → **1440×2484**（真放大） | 111.1 s |

出图质量：动漫人物线条清晰、无糊、颜色与原文一致（`color_correction=lab`）。

### ⚠️ 最大的坑：`resolution` 是「目标短边」，不是倍率

填 1080 而原图短边 1168，**结果是缩图**，而且**不报错**。

**集成时必须校验**：`resolution > 原图短边`，否则拒绝提交。代码见 `技术实现.md` §7.3.1 的 `assertReallyUpscaling`。
