## §4 已知的坑（踩过就别再踩）

| # | 坑 | 教训 |
|---|---|---|
| 1 | 把文档里已有的东西当成"新发现" | 引用前先 grep 原文，`excerpts/` 里可能早就写了（`EX07` L145 那次） |
| 2 | 查文件"不存在"就下结论 | 只查了一个目录。**先 `Get-ChildItem -Recurse` 全盘找，再说没有** |
| 3 | 人日汇总表与 WBS 对不上 | **每个里程碑的子任务逐项求和，当场核对**，不靠估 |
| 4 | 计划表漏掉整块工作 | v2.0 漏了 M13 小说创作（入口 C），足足 20 人日。**列范围时把"入口"全查一遍** |
| 5 | 概念混称 | "三个入口"= 喂料方式（A/B/C）；MCP/API/GUI = 访问方式。两回事 |
| 6 | pnpm 12 默认拒跑依赖 install 脚本 | 首次 install 报 `ERR_PNPM_IGNORED_BUILDS`（esbuild）。`pnpm-workspace.yaml` 里 `allowBuilds: esbuild: true` 已配好，新里程碑不用再踩 |
| 7 | `DramaPaths` 四字段读写不分 | 初版把 legacy 回退做进 `configFile`，`saveConfig` 会写回旧目录。**规范缺陷要在调用侧打补丁之前修签名**——签名表达力不足是根因 |
| 8 | 根目录跑 tsx 探针报 `ERR_MODULE_NOT_FOUND` | 根 package.json 不依赖 shared。**探针必须放 `apps/core` 下跑**才能解析 workspace 链接 |
| 9 | TS 运行时判断不收窄联合类型 | `v6.kind() === "ipv6"` 不让 TS 窄化 `IPv4 \| IPv6`。用 `instanceof`（`ipaddr.IPv6`） |
| 10 | 子代理窗口会死于 429，遗言都没有 | 两个窗口同时死、closing message 为空。**纪律**：每完成一块立刻写日志；主会话验收只看盘上文件不看回报；代写日志必须标「主会话代记」 |
| 11 | team 名额 8 满后死窗口占位无法清理 | `maxMembers` 是 immutable roster。**长会话省着用 spawn_teammate**；单块任务用一次性 subagent（不占名额） |
| 12 | 子代理死于 content_filter（R18 长文本） | 把摘录 R18 原文整段读入后**连续大批量写露骨文本**会触发 provider 审查。**R18 内容写入必须切小批次**（单次写入量小、分文件落盘）；死因要靠「日志末条 + 盘上产物差集」验尸——代理自己的记忆可能停在死前，被唤醒后会把残留窗口误当事实（见 M03 [003]/[004] 双 CORRECTION 教训） |
| 13 | append-only 日志的双 CORRECTION 叠放 | 代理被唤醒后基于残缺记忆「纠正」正确记录是真实风险。**主会话代记时保留全部叠放层**，读者从 [001]→[CORRECTION #1]→[CORRECTION #2] 能看到完整归因链，这比一条「正确」记录更有价值 |
| 14 | vite-node 把 .js 编译缓存落源码目录并**遮蔽同名 .ts** | NodeNext 解析下 `.js` 优先于 `.ts`，旧产物会让新源码的修改失效、tsc 报幽灵错（TS2307 找到不存在的缺失）。**症状**：文件在、导出在、tsc 仍说找不到。**处置**：清 src/test 下全部 .js + node_modules/.vite 缓存后重跑 |
| 15 | 子代理的相对路径层级笔误（`../` 少一级） | `media/tts/` 引 `../gpu/` 实际落 `media/gpu/`（不存在）。**排查工具**：`tsc --traceResolution` 直接显示候选路径——表象诡异时先看解析轨迹再猜 |
| 16 | stdio: "ignore" 导致类型推断成 never | spawn 的 stdio 设 ignore 后 stdout 类型为 null，`?.on` 链推断 never。**修法**：不用消费的流也保持 "pipe"，或显式类型断言 |
| 17 | **文档承诺 ≠ 盘上实现**（本轮最大教训） | 28 个 MCP 工具文档齐全但只注册了 1 个；37 个 REST 端点只落地 2 个；零持久化层；六个已交付模块外部引用数全为 0。**教训**：里程碑「完成」指的是各自模块的纯逻辑完成，**不等于装进系统**。验收时必须实测「外部引用数」与「注册表条目数」，不能只看测试绿 |
| 18 | 一个字段指两件事 | `ProjectSettings.fps: 24\|30` 同时被当成"生成帧率"和"交付帧率"，而生成恒 24（模型固定）、交付 = 24×插帧倍率。**教训**：字段命名要指名所属侧（`generationFps` vs `interpolateMul`），合并语义会在下游炸 |
| 19 | 照抄来的孤儿选项 | `fps: 30` 既非 H3 能出、也非 RIFE 能出（24×1.25 在 17n+5 网格上出半帧 303.75）。**教训**：参考项目搬过来的枚举值要用算术验一遍能不能落地，能验的当场验 |

## §8 日志纪律（每次派子代理必须交代）

### 8.1 一个里程碑一个文件

| 角色 | 写哪 |
|---|---|
| 子代理 | **只写自己那个** `docs/worklog/M{NN}.md` |
| 主会话 | 更新 `docs/WORKLOG.md` §3 索引、§4 跨里程碑记录 |

**为什么分文件**：多个子代理并行时写同一个文件会打架。分文件 = 零冲突。

### 8.2 只能追加，不能减少

| 允许 | 禁止 |
|---|---|
| ✅ 末尾追加新条目 | ❌ 修改已有条目 |
| ✅ 追加 `[CORRECTION #N]` 修正 | ❌ 删除任何条目 |

### 8.3 每完成一个板块立刻写

不攒着写——**攒着写 = 429 时全丢**。判断标准：

| 情况 | 是否写 |
|---|---|
| 完成一个子任务 | ✅ 写 |
| 完成一个里程碑 | ✅ 写，标 `[里程碑完成]` |
| 卡住了、放弃某方案 | ✅ 写，**这条最值钱** |
| 发现前面错了 | ✅ 写 `[CORRECTION #N]` |
| 只读文件没产出 | ❌ 不写 |

### 8.4 派子代理的 prompt 必须包含这段

```
你要写日志：docs/worklog/M{NN}.md
- 每完成一个子任务立刻追加一条 [00N]，格式照该文件内的模板
- 七个字段都要填，「踩到的坑」和「关键决定」最重要
- 只能追加，不能修改或删除已有条目
- 发现前面写错了，追加 [CORRECTION #N]，不要改原条目
```

**漏了这段，子代理就不会写日志**——它不知道有这个要求。
