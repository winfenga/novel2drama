# MiniMax H3 Hybrid 专项规则（关键帧 ＋ 参考素材 混合生成 · R18）

> **输出壳与 Ref2VA 完全相同** —— 六段（`subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music`）＋ 末尾技术排除行。字段名、标签体系、枚举值、`<Audio N>` / `<Video N>` 多参规则（`ref2va-rules.md` 第 3.5 节）、`ref2va-rules.md` 第 6 节的自检清单**全部沿用**，本文件**不重复**。
>
> **本文件只管 Ref2VA 规则里没写清的四件事**：① 什么时候判成 Hybrid；② **`<Picture N>` 的编号契约**；③ 关键帧（首帧 / 尾帧）在六段里怎么写；④ **开场纪律：首帧 → 剧情不得超过 0.5 秒**（第 3.5 节，硬性 —— **目的是保住连续链接缝的连贯**，不是节奏审美）。
>
> 即：**Hybrid = Ref2VA 的六段壳 ＋ 一个被钉死的编号契约 ＋ 关键帧写法 ＋ 开场 0.5 秒起步（保连贯）**。术语上它是「关键帧 ＋ 参考素材」的混合任务，**不是**"混合权重的模型"、也不是壳的变体。

## 1. 什么时候走 Hybrid

**成立条件（两条同时满足，缺一不可）**：

1. **至少一张关键帧** —— 用户明确指出某张图是目标视频的 **0.00 秒首帧**（工作流字段名 **`first_frame`**）或**末帧**（字段名 **`last_frame`**）。
2. **至少一份参考素材** —— 另有参考图 / 参考音频 / 参考视频，用来锁定人物身份、服装、场景、姿态或声线。

判定对照（与 `SKILL.md` E1 的自动判定同源）：

| 素材构成 | 走哪条 | 为什么 |
|---|---|---|
| 只有一张图，且它就是 0.00 秒首帧；**没有**别的素材 | **I2VA** | 没有参考素材可混，Hybrid 不成立 |
| 只有关键帧（首帧 / 首尾帧）；**没有**别的素材 | **I2VA** | 同上 |
| 只有参考素材，**没有**任何一张被指认为关键帧 | **Ref2VA** | 缺关键帧，Hybrid 不成立 |
| **关键帧 ＋ 参考素材**（两类都有） | **Hybrid** | 本文件 |
| 点名 Hybrid 但只给了一类 | **不出词** → 按第 4 节说明并给选项 | 不默默改路 |

> **不要**为了凑成 Hybrid 就把某张纯参考图虚构成"首帧"；也不要为了走 Ref2VA 就把用户明确指认的首帧降级成普通参考图。素材类别由**用户指认 ＋ 实际画面**共同决定。

### ★ 多参考连续链：第 2 条起默认走 Hybrid（硬性 · 2026-10-03 用户指定）

**背景**：本技能是**照剧本生成提示词**的技能，一条作品的多条片段构成本质上是一条链，**首要目标是连贯**。而纯 Ref2VA 的每一条都是**独立生成** —— 第一帧由参考图重新生成，**不保证与上一条的实产尾帧对齐**：姿势、朝向、画框左右、人物距离、光线、道具持握都会漂，连起来看就是一顿一顿的。

**因此**：

| 位次 | 走哪条 | 关键帧 |
|---|---|---|
| **第 1 条** | **Ref2VA** | 无 —— 没有上一条可接，天然无从 Hybrid |
| **第 2 条起** | **Hybrid** | **接上一条的实产尾帧**，写成本条 `first_frame` |

**接帧做法**：把上一条的实产尾帧（用户上传的那张「接着这张动」的图）挂成本条 `first_frame`，参考素材照旧从 `<Picture 1>` 排（见第 2 节编号契约）。由此第 0 帧锁死在上一条的收尾画面上，链才接得上。

**取尾帧的纪律**：仍受本文件第 1 节「素材来源纪律」约束 —— 关键帧**只能用用户本条实际上传的图**。用户没上传尾帧时：

1. **主动问一句**：「这条要不要接上一条的尾帧？接上才能保证连贯（走 Hybrid、把尾帧当 `first_frame`）」；
2. 说明**不接的代价**：本条第一帧会重新生成，与上一条收尾可能对不上；
3. 用户说不接 → 按不接走，并在本条文件头注明「本条不与上条逐帧对齐」。

**提醒用语（固定）**：凡用户的选择会影响连贯性时，主动提醒：

> 「建议用 **Hybrid** —— 把上一条的尾帧接成 `first_frame`，**能保证这一条与上一条连贯**；纯 Ref2VA 不接帧，画面会跳。」

**冲突处理（不默默改路）**：用户点名「第二条也走纯 Ref2VA」或其点名分支与本铁律冲突时，按 `SKILL.md` E1 的统一做法 ① 说明冲突与代价 → ② 给出「①走 Hybrid 接帧（推荐）／②坚持你的分支（不保证接帧）」两个选项 → ③ 等确认后出词。**不得**因为用户没说「要 Hybrid」就默认放掉接帧 —— **多参考场景下只要存在前序片段，默认就该接帧走 Hybrid**。

### ★ 逐条串行出词：出完 01 停下等尾帧（硬性 · 2026-10-03 用户指定）

**接帧依赖的尾帧在出词时并不存在** —— 它要等用户拿 01 的提示词跑完视频、抽出尾帧才能给出。因此连续链**不能批量出词**：

> **Hybrid（及整条连续链）必须一段一段出。出完 01 立即停下，等用户把 01 的实产尾帧图交回来，用它当 02 的 `first_frame`，再出 02。**

**一条一个来回**：

| 轮次 | 你做什么 | 停下等什么 |
|---|---|---|
| 1 | 出 **01**（Ref2VA） | 用户生成 01 → **抽回 01 实产尾帧** |
| 2 | 用它当 `first_frame`，出 **02**（Hybrid） | 用户生成 02 → **抽回 02 实产尾帧** |
| 3 | 同上，出 **03** | 抽回 03 尾帧 |
| … | 类推至链尾 | — |

**硬性要求**：

1. **一次只出当前这一条**，出完**明确停下**，固定句式收尾：「`NN` 已成词。请用 `NN` 生成视频，把**尾帧**导出给我 —— 它是下一条的 `first_frame`。」
2. **不得提前出下一条**（哪怕是「预告」）—— 后面条目的 `first_frame` 此时不存在，写出来只能靠猜，而**猜出来的关键帧比没有更坏**：它会写进 `retention_analysis` 与 `[Shot 1]` 锚点句，让模型去逐像素复现一张并不存在的图。
3. **E3 可以一次登记全链**（目录里 01–0N 全列出，状态 `待出词`），**但出词仍是逐条串行** —— 登记是计划，出词是执行。
4. **用户催「一起给」时**：说明代价，给两个选项 —— ①按串行逐条来（推荐，保连贯）；②确实要一次性批量，则后续条目按**纯 Ref2VA** 出（不接帧、不保证逐帧对齐），并提醒「用串行 Hybrid 才能保证连贯」。**等确认再动手。**
5. **用户一次性把尾帧全给了**（手工预出所有关键帧）→ 按正常流程逐条出，但**仍逐条落盘**，不合并成一条。
6. **目录状态流转**：出词落盘 → `待尾帧`（球在用户手）→ 用户交回尾帧 → `已成词`（球在自己手）。**出完不许直接写 `已成词`**，除非是链尾或单条作品。

### ★ 链条第三条：接帧条目开场不得静态停留（硬性 · 2026-10-10 用户指定，为保连贯）

接上一条的实产尾帧之后，**不许在首帧上停** —— 从 `first_frame` 的 0.00 秒到本场**第一个剧情节拍**启动，**不得超过 0.5 秒**。

**为什么是链条规则**：上一条的末帧通常**正处在运动之中**，本条从它接上去；先定格／静止片刻再动，等于在**上一条的运动中途插进一段静止**，接缝处会顿一下，成片立刻显出"两段"的拼接感 —— 前面接帧、串行等尾帧的功夫在接缝处被抵消。

**它与另两条链上规则并列**：① 走连续链（保帧接得上）→ ② 逐条串行（保关键帧是真的）→ ③ **开场 ≤0.5 秒（保接上之后不停）**。

**规则细节、禁写清单与写法示例见第 3.5 节。**

### ⚠️ 素材来源纪律（硬性 · 2026-10-03 实战踩坑固化）

**关键帧只能来自「用户本条消息里实际上传的图」，不得取用作品库里已有的历史产出图。**

实战翻车记录：某条曾把 `ref-02-tail.jpg`（**该条自己上一轮生成的历史尾帧**，早已存在库里）当成「本次的末帧素材」写进提示词，整条写成"首尾帧双锚点"。而用户本次**只上传了首帧那一张**，根本没给尾帧 —— 被用户当场指出「我是上传了首帧，没有尾帧」。

**判定纪律**：

1. **数一遍用户本次实际附了几张图** —— 只有这几张可以成为关键帧或参考素材。库里存在的其它图（历史尾帧、旧版首帧、废弃稿）**默认不参与本条**。
2. **历史产出图 ≠ 本次素材**。`ref-0N-tail.jpg` 这类「上一条的实产尾帧」是**链条记录**，不是「用户这次给的东西」。它要成为本条的首帧，必须是**用户点名要接**（如"接着这张动"）或**本条正文明确以"上一 clip 的末帧"身份引用**。
3. **不要把「我希望这条收到哪里」当成「用户给了末帧」**。想要收尾落在某构图，就**在正文里写清楚动作与结果**，而不是凭空挂一个尾帧锚点。
4. **不确定就问**：问一句「本次只接了首帧，还是首尾帧都要锁？」比写错一条便宜得多。

> 交叉检查：`<Picture N>` 的**总数**应等于「用户本次实际上传张数」。总数对不上 ⇒ 混入了历史图，回头核对。


**用户说法的识别**（同义一并认）：

| 用户说法 | 采用分支 |
|---|---|
| 「走 Hybrid」「用 hybrid 模式」「混合」「hybrid 分支」「首帧 + 参考一起」「关键帧 + 参考混合生成」 | **Hybrid** |
| 「这张是首帧，另外这几张是人物 / 服装 / 场景参考」 | **Hybrid**（用户自己已把两类都给全了） |
| 「这张是首帧，接着它往下动」（且没有别的素材） | **I2VA**，不是 Hybrid |
| 「这几张当参考」（没有任何一张被指认为首帧 / 末帧） | **Ref2VA** |

生效范围与另三条一致：用户指定后本轮及后续同类场景**默认沿用**，直到改口或说「自动」；每次定完都用一句话复述「当前走 X 分支（来源：用户指定 / 自动判定 / 兜底）」。

## 2. 编号契约（硬性 · 2026-10-03 用户最终裁定）

**关键帧不用 `<Picture N>` 编号，改用工作流字段名独立标识；`<Picture N>` 全部留给参考图，从 `<Picture 1>` 起按用户给图顺序排。**

| 素材类别 | 标识写法 | 是否占 `<Picture N>` 号 | 编号起点 |
|---|---|---|---|
| **首帧**（0.00 秒那一帧） | **`first_frame`** | **不占** | — |
| **尾帧**（末帧） | **`last_frame`** | **不占** | — |
| **参考图**（人物 / 服装 / 场景 / 姿态…） | `<Picture 1>`、`<Picture 2>`、… | 占 | **恒从 `<Picture 1>` 起** |

- **只接首帧**：`first_frame` 独立成行；参考图 `<Picture 1>` / `<Picture 2>` / `<Picture 3>`… 按用户给图顺序。
- **首帧 ＋ 尾帧**：`first_frame` 与 `last_frame` 各独立成行；参考图仍从 `<Picture 1>` 起（**不因关键帧顺延**）。
- **只接尾帧**：`last_frame` 独立成行；参考图仍从 `<Picture 1>` 起。
- **关键帧不占号 ⇒ 参考图不因关键帧数量而移位**，多接几个关键帧也不影响参考图编号。
- `<Audio N>` / `<Video N>` **各自独立编号**，按 `ref2va-rules.md` 第 3.5 节从 1 起。

**★ 写法格式（用户指定）**：「格式同 Picture，名字换成 `first_frame`」。即 `<Picture N>` 的位置写 **`first_frame`** / **`last_frame`**（**反引号包裹的字段名**，带下划线），**不写** `<First Frame>` / `<Picture First>` 之类自造标签。

举例（首帧 ＋ 3 张参考图）：

```text
subject_definitions:
<Subject 1>: the adult woman whose face, glasses and body proportions come from <Picture 2>; her hair length, figure and waist come from <Picture 1>.
<Subject 2>: the adult man whose physique, build and hair come from <Picture 3>.
first_frame: the exact 0.00-second first frame of the target video, <画面描述>. ...
```

> **⚠️ 与旧版规则的差异（重要）**：本文件 2026-10-03 之前的版本曾写「关键帧排最前占号（`<Picture 1>` = 首帧、`<Picture 2>` = 尾帧、参考图顺延）」，**该写法已被用户明确否定**。若你（或历史条目）看到关键帧被编成 `<Picture N>`，一律按本节改正：关键帧 → 字段名不占号；参考图 → 重新从 `<Picture 1>` 排。

**实现附注**：ComfyUI 侧 `MiniMaxH3AudioConditioningT8` 的 `task_type = Hybrid` 与 core 原生 `MiniMaxH3ReferenceToVideo` ＋ `Add Guide for MiniMax H3`，两者都按 `first_frame` / `last_frame` 字段名引用关键帧；本节写法对两条实现通用。若用户另有指定，以用户指定为准。

## 2.5 已有条目改判 Hybrid 时的重排步骤（实战补入 2026-10-03 · 2026-10-03 按最终裁定修订）

**触发**：某条原本按 Ref2VA（或 I2VA）出了词，事后发现它其实**同时具备关键帧与参考素材**（或用户指出「有首尾帧＋人物参考图就该走 Hybrid」）⇒ 必须改判 Hybrid 并**重排全部编号**。

**为什么必须重排**：关键帧在 Hybrid 里改用字段名标识、**不占号**，`<Picture N>` 全部让给参考图并从 1 起。若原条目把关键帧编成了 `<Picture 4>` 之类，就会**挤掉参考图的号**，必须整体前移。**只改分支名而不重排编号 = 出词必错**。

**标准重排步骤**：

1. **先分清两类素材**：本条有几张被指认为首帧／末帧？（0 张 → 不是 Hybrid，走 Ref2VA）另有几张纯参考图？
2. **列出新旧映射表**，关键帧走字段名、参考图整体前移。例（旧版把首帧编成了 P4）：

   | 旧写法 | 新写法 | 内容 |
   |---|---|---|
   | `<Picture 1>` | `<Picture 1>` | 参考图①（女全身） |
   | `<Picture 2>` | `<Picture 2>` | 参考图②（女脸） |
   | `<Picture 3>` | `<Picture 3>` | 参考图③（男全身） |
   | **`<Picture 4>`** | **`` `first_frame` ``** | **首帧（独立标识行，不占号）** |
   | **`<Picture 5>`** | **`` `last_frame` ``** | **末帧（如有；独立标识行，不占号）** |

   > 若旧版是「关键帧占号在最前」（如 `<Picture 1>` = 首帧、参考图从 P2 起），则参考图**整体前移**：旧 `P2`→新 `P1`、旧 `P3`→新 `P2`…，首帧改 `first_frame`。

3. **逐处改（共 7 处，漏一处即不一致）**：① 标题里的分支名；② `subject_definitions` 的身份锚点句（`<Subject N>` 改引参考图新号）；③ 首帧定义句 → 改为独立行 `first_frame: the exact 0.00-second first frame of the target video, ...`（**不是** `<Picture N>: ...`）；④ 尾帧定义句 → `last_frame: the exact last frame of the target video, ...`；⑤ `summary` 前缀 → `[keyframe completion + reference generation]`；⑥ `retention_analysis` 关键帧行 → `` `first_frame` ([Shot 1] 的 0.00 秒首帧): fully_preserved - ... ``；⑦ `detailed_description` 里全部编号（含身份句、`[Shot 1]` 开场锚点句 → `opens exactly on the first_frame image`、结尾收束句）。
4. **头部引用图清单同步**（易漏）：文件头的「参考图 → 编号」对照表要按新契约重列，关键帧单独标 `first_frame`（不占编号）。
5. **收尾自检**：跑一遍第 6 节 Hybrid 专属清单 ＋ `ref2va-rules.md` 第 6 节完整清单；特别确认 `[Shot 1]` 是从 `first_frame` 启动的。
6. **改前备份**：`_备份-<时间戳>-改Hybrid/`。

> **自动化提示**：批量检查编号一致性可用「正文块内各号出现次数」是否自洽来判断 —— 关键帧用字段名出现多次（定义行＋retention＋Shot1＋收尾），参考图只在身份句和 `[Shot 1]` 里出现。若正文里仍出现 `<Picture N>` 被当作关键帧（如某号的出现次数等于关键帧该有的次数），说明漏改。

## 3. 关键帧在六段里怎么写

### 3.1 `subject_definitions`

- **首帧**单独一行，**行首用字段名 `first_frame`**（不是 `<Picture N>`），写明它是目标视频的 0.00 秒画面，**只描述画面上有什么** —— 不在这一行写声线、不写性格：

  ```text
  first_frame: the exact 0.00-second first frame of the target video. <主体在画面里的位置与比例、景别、机位、姿态、重心、朝向与视线落点、服装状态、道具及其持握方式、光线>.
  ```

- **尾帧**同样单独一行，**行首用字段名 `last_frame`**，写明它是目标视频的**最后一帧**，并把同一组构图事实写全：

  ```text
  last_frame: the exact last frame of the target video. <同一组构图事实>.
  ```

- **角色身份、声线一律绑到真正的参考图**（`<Picture N>`），不绑关键帧：

  ```text
  <Subject 1>: the adult woman whose face, black updo and body proportions come from <Picture 1>; her voice is the timbre referenced by <Audio 1>.
  ```

- 关键帧**不建立新的 `<Subject N>`** —— 它是目标视频自己的一帧，不是可复用的可见单元。

### 3.2 `summary`

- 任务类型前缀：**`[keyframe completion + reference generation]`**（关键帧锚定 = `keyframe completion`；参考素材 = `reference generation`）。
- 另有声线参考时按 `ref2va-rules.md` 第 3.5 节叠加：`[keyframe completion + reference generation + audio reference]`。
- **只使用素材实际支持的类型**；本节**不引入新标签**。

### 3.3 `retention_analysis`

- 每个关键帧**单独一行**，**行首用字段名**（`first_frame` / `last_frame`），默认 `fully_preserved`（用户要求"这一帧必须一模一样"时同样是 `fully_preserved`；只有关键帧仅作构图参考、允许偏移时才降为 `partially_preserved`）：

  ```text
  `first_frame`（[Shot 1] 的 0.00 秒首帧）: fully_preserved - ...
  `last_frame`（[Shot 1] 的末帧）: fully_preserved - ...
  ```

- 参考素材仍按 `ref2va-rules.md` 第 3 节各自的归因写；`<Audio N>` 一律 `reference`。

### 3.4 `detailed_description`

四条硬性：

1. **`[Shot 1]` 必须从 `first_frame` 的内部启动**：从这张图已有的景别、机位、姿态、重心、朝向与道具持握状态**直接开始动作**；**第 0 帧不得换姿势、换构图、换视线、换道具持握**。写法用 `opens exactly on the first_frame image`（**不是** `opens on <Picture 1>`）。若同时挂了尾帧，则见第 2 条。
2. **★ 首帧到剧情不得超过 0.5 秒**：`first_frame` 只锁第 0 帧的构图，**不是静态定格** —— 本场第一个剧情节拍必须在 **0.00–0.50 秒**内已经启动。细则见第 3.5 节。
3. **挂了尾帧就必须收在尾帧上**：最后一个 `[Shot N]` 的**末帧**要精确落成 `last_frame` 表现的位置、姿态、视线、接触关系与道具状态。中间过程可自由设计，但**不得中途跳到尾帧**，也不得让尾帧的构图凭空出现 —— 尾帧是整条视频的**收束目标**，不是最后一秒才贴上去的画面。
4. **两种朝向约束叠加**：既要从首帧承接朝向（`nsfw-template.md` 第五节第 5 条的 `Facing:` 句，逐人写清），又要让末帧落回尾帧的朝向。**中间任何转向都必须写成转身动作**，不得瞬移式改向。

### 3.5 ★ 首帧 → 剧情不得超过 0.5 秒（硬性 · 2026-10-10 用户指定 · 目的是保连贯）

> **⚠️ 先读懂这条的目的：它是「连贯性」规则，不是节奏审美。** 别把它当成"开头别太闷"的风格偏好 —— 它和「多参考必须走连续链」「连续链必须逐条串行出词」是**同一族的第三条**，三条共同服务一件事：**让 N 条片段看起来是一条**。

**为什么必须压缩这段静止**：

本技能的多片段作品是一条**连续链**。第 2 条起的 Hybrid，其 `first_frame` **就是上一条的实产尾帧** —— 而上一条的**末帧通常正处在运动之中**（抽送、位移、转身、呼吸节奏都还在走）。本条视频正是从这一帧接上去的。此时如果**先在首帧上静态停留**（定格 / 静止片刻 / 缓缓起手再动），就等于在**上一条的运动中途硬插进一段静止**：

- 接缝处会**顿一下** —— 上一条正在动的画面，到本条突然冻结，再重新启动；
- 观众眼里这**立刻变成两段**，"上一条 + 下一条"的拼接感出来了；
- 前面为了接帧（Hybrid）、为了串行等尾帧所做的一切，**在接缝处被这一段静止抵消掉**。

**所以**：

> **从 `first_frame` 的 0.00 秒起，到本场剧情（动作 / 台词 / 位移 / 表情变化等第一个剧情节拍）真正启动为止，不得超过 0.5 秒。**
> 即：**剧情必须在 0.00–0.50 秒内起步**。**0.5 秒是上限、不是目标值 —— 越短越好**，理想是首帧一挂上剧情就已经在走。

**三条链条规则的分工**：

| 规则 | 管什么 |
|---|---|
| 多参考必须走连续链（第 1 节） | **帧接不接得上** —— 第 2 条起接上一条实产尾帧 |
| 连续链必须逐条串行出词（第 1 节） | **关键帧是不是真的** —— 不许靠猜 |
| **本条（首帧 → 剧情 ≤0.5 秒）** | **接上之后不许停** —— 不许在接缝处插静止 |

**这条与第 3.4 节第 1 条的关系**：第 1 条管「**从哪开始动**」（必须从 `first_frame` 的构图内部起手，不得换姿势／构图）；本条管「**多久之内必须动**」（≤0.5 秒）。两条叠加 ⇒ **在同构图内，0.5 秒内动起来**。遵守本条**不等于**允许第 0 帧换姿势 —— 那仍然禁止。

**适用范围**：所有 Hybrid 条目一律执行（开场静态停留本身就会拖垮观感）；**链上条目（第 2 条起）是硬性接缝，没有商量余地**。非链上的 Hybrid（用户手工给了一张独立首帧）同样照此办。

> **同族规则与平行条文**：本条只是把「首帧锚定 → 不许静止」用在 Hybrid 上。**`I2VA` 有同一条硬性，写在 `i2va-rules.md` 第四节**（`<Picture 1>` 即 0.00 秒首帧时同样 ≤0.5 秒）；`Ref2VA` 挂了首帧锚点时同理。T2VA 无首帧，不受限。三条链上规则的全景见 `SKILL.md` E1 前置铁律之三。

**写法规矩**：

1. **锚点句要同时写出「承接」与「启动时限」**：在第 3.4 节第 1 条的 `opens exactly on the first_frame image` 之后，紧接着（同一句或下一句）写清两件事 —— ① 动作已在 **0.5 秒内启动**；② **链上条目**还要写明动作是从上一帧**延续下来的**、中间没有停顿：

   ```text
   opens exactly on the first_frame image; the motion carried in from the previous clip continues without any hold, and her <本场第一个剧情节拍> is already underway within the first 0.5 second.
   ```

   **不得**只写 `opens exactly on the first_frame image` 就转去描写静止画面细节 —— 那等于给模型发了一张"先停一下"的许可。
2. **禁止任何"停留"写法** —— 正文里不得出现下列意思（中英文皆禁）：

   | 禁用 | 英文禁用写法 |
   |---|---|
   | 镜头在首帧上停留片刻 | `the camera holds still on the image`, `the frame holds`, `holds on the opening frame` |
   | 静置 / 定格一秒后再动 | `remains motionless`, `freezes for a moment`, `stays still before` |
   | 先展示画面再开始动作 | `a brief pause before the action`, `the shot lingers`, `slowly comes to life` |

   也不得用「先慢慢抬眼／先缓缓呼吸」这类**无剧情节拍的缓起句**吃掉前 0.5 秒 —— **抬眼、呼吸、视线移动不算剧情节拍**，不能拿它们充当开场动作。
3. **首帧的画面信息不靠停留来交代** —— 景别、机位、姿态、服装状态、道具持握这些事实**由 `first_frame` 这一帧本身承担**（见第 3.1 节的定义行），**不需要**在视频里再"摆"一遍给观众看。原地静止 1 秒展示画面 = 在接缝上白送 1 秒静止，最伤连贯。
4. **叙事节奏随之改写（这是压缩后的副作用，不是本条的目的）**：`nsfw-template.md` 第五步的「5 秒：清纯/日常 0–1.5 秒 → 转变 1.5–3 秒」**在 Hybrid 里按下列覆盖** ——

   | 时长 | 通用节奏（`nsfw-template.md`） | **Hybrid 覆盖后的节奏** |
   |---|---|---|
   | 5s | 铺垫 0–1.5 → 转变 1.5–3 → 高潮 3–5 | **铺垫 0–0.5 → 转变 0.5–2.5 → 高潮 2.5–5** |
   | 更长时长 | 按比例放大（15s 建立 0–3） | **建立段一律压到 0–0.5 秒，其余阶段按剩余时长等比铺开**，结尾仍留 0.4–0.8 秒余韵 |

   为什么能压：Hybrid 的「铺垫」已经由 `first_frame` 那一帧**前置完成**（那一帧本身就是上一条的收束画面、已经把开场信息交代完了），视频里再留铺垫就是重复 —— 而且是**带停顿的重复**。
5. **与尾帧的配合**：压掉开头的铺垫**不会**减少剧情节拍 —— 内容塞不下照样按「① 加时长 → ② 拆条 → ③ 绝不删节拍」处理（`SKILL.md` E5）。**不得**因为本条要求前 0.5 秒起步就把中间的节拍砍掉。**本条文压缩的是"接缝处的静止"，不是剧情。**

**唯一例外**：**用户明确要求"先定格 X 秒再动"时按用户要求办**（用户指令优先），并在该条文件头的衔接说明里注明「本条开场按用户要求定格 X 秒」，同时确认 X 值。**链上条目要额外提醒一句代价**：「这一条接的是上一条的尾帧，定格 X 秒会在接缝处停一下，成片会顿 —— 确认要这样吗？」用户坚持才照做。除此之外不得自行放长。

**自检问句**：把本条正文读一遍 —— **0.00–0.50 秒这一段里，有没有至少一个真正的剧情节拍在发生？** 没有 ⇒ 改。

## 4. 点名 Hybrid 但只给了一类素材时怎么办（不默默改路）

按 `SKILL.md` E1 的统一做法处理，三步：

1. **说明冲突与代价** —— Hybrid 要求两类素材同时在；只给一类时：
   - **只给关键帧** → 实际等于 **I2VA**（首帧）或首尾帧锚定，**没有任何参考素材**，人物身份只能靠这张关键帧自己锁；
   - **只给参考素材** → 实际等于 **Ref2VA**，**没有关键帧**，视频第一帧由参考图生成、**不保证**与任何一张图逐像素对齐。
2. **给两个可执行选项** —— ① 补上缺的那一类素材后走 Hybrid；② 按上面降级走 **I2VA 或 Ref2VA**（注意**壳会变**：I2VA 是「指令行 ＋ 三字段」，Ref2VA / Hybrid 是六段）。
3. **等用户确认后再出词**，不要自己挑一条就往下写。

## 5. 与相邻路线的关系

| | I2VA | Hybrid | Ref2VA |
|---|---|---|---|
| 关键帧 | 必须有（＝唯一那张图） | **必须有 ≥1** | 可选；有则按纯 Ref2VA 顺序编号 |
| 参考素材 | **不得有** | **必须有 ≥1** | 必须有 ≥1 |
| 输出壳 | 指令行 ＋ 3 字段 | **六段** | 六段 |
| 关键帧标识 | 隐含为唯一图 | **`first_frame` / `last_frame` 字段名，不占 `<Picture N>` 号** | `<Picture N>`（占号） |
| `<Picture 1>` 是什么 | （无） | **第一张参考图**（关键帧不占号，故恒为 P1） | 第一张参考图 |
| 详细规则 | `i2va-rules.md` | 本文件 ＋ `ref2va-rules.md` | `ref2va-rules.md` |

- **Hybrid 与 Ref2VA 共用同一个壳**：六段结构、`<Subject N>` / `<Picture N>` 标签体系、枚举值、多参（`<Audio N>` / `<Video N>`）规则、第 6 节自检**全部沿用 Ref2VA**；Hybrid 只额外钉死**关键帧用字段名标识、不占号**与**关键帧写法**（本文件第 2、3 节）。
- **I2VA 是 Hybrid 的退化形态**：只有首帧、没有任何其他参考素材时 Hybrid 不成立，退成 I2VA。反过来，**I2VA 的任务一旦补上参考素材，就应当改走 Hybrid**（壳也随之从三字段换成六段）。
