## [001] 2026-11-10 21:00 · M05-1~M05-5 · LLM 后端接入五件套一次交付

- **做了什么**：
  M5-1 `backends.ts`：pickBackend 四步判定（llm_no_backend / llm_no_role 两码分开，message 列候选），外加 `expectPickConfig` 把 `cfg: unknown` 显式收窄（不合法抛 invalid_param，不猜）。
  M5-2 `netPolicy.ts`：isPrivateAddress（ipaddr.js `range()`，覆盖 loopback/private/linkLocal/uniqueLocal/carrierGradeNat/unspecified/reserved + IPv4-mapped 重判）+ assertBaseUrl（协议白名单先行，local:true 才放行内网，否则 llm_private_url）。
  M5-3 `chat.ts`：llmChat，120s AbortController 超时；401/403→llm_auth、404→llm_model_not_found、其余/网络错/abort→llm_unreachable，一律 502；响应缺 content 字段也抛 llm_unreachable，不造默认值。
  M5-4 `retry.ts`：chatWithRetry 按报错文案 `/temperature/i` 重试一次（temperature=1），重试失败原错上抛；stripReasoning 正则照 architecture L819-832 逐字抄。
  M5-5 `connectivity.ts`：testBackends，GET {baseUrl}/models，target="*" 全测 enabled；单后端失败进 ok:false+detail 不中断报告。
  授权豁免：`config/types.ts` ROLES 加第四值 "vision" + RoleRoutingSchema 加 vision 键（decision-log §21 第 3 条，漂移 F5）。
- **改了哪些文件**：
  - 新增 `apps/core/src/llm/backends.ts` / `netPolicy.ts` / `chat.ts` / `retry.ts` / `connectivity.ts`
  - 新增 `apps/core/src/llm/backends.test.ts` / `netPolicy.test.ts` / `chat.test.ts` / `connectivity.test.ts`
  - 修改 `apps/core/src/config/types.ts`（仅 ROLES 加 "vision" 与 RoleRoutingSchema 加 vision 键，M0 冻结区唯一授权豁免）
- **关键决定**：
  1. Backend 类型直接复用 config 冻结的 `LlmBackend`，不另造平行类型（spec §1.2 的 Backend 接口与它字段一一对应，`local?` 可选一致）。
  2. isPrivateAddress 按 spec 签名收 URL 字符串，`new URL` 失败时按裸主机名兼容处理，测试两形态都覆盖。
  3. llmChat 的 catch 仅做错分类重包装（非 DramaError → llm_unreachable，原错挂 cause），不是吞错降级；retry.ts 的 catch 是 spec §3 授权的「重试一次」吞点，connectivity 的吞错是测试工具结构化输出（不产生业务默认值），两处均有注释。
  4. 调用方 signal 与 120s 超时控制器分离：signal 只提前取消，不重置超时计时（spec 只冻结 120s）。
- **踩到的坑**：
  仓库 `apps/core/vitest.config.ts` 的 include 只收 `test/**`，而 spec 冻结 M5 测试位置在 `src/llm/*.test.ts`。不擅改 vitest.config（不在授权清单），用放 %TEMP% 的临时 config 跑通（`vitest run --config <temp>`），仓库文件零改动。主会话后续若想让 `pnpm -C apps/core exec vitest run` 直接收编 src/llm 测试，需把 include 扩成 `["test/**/*.test.ts", "src/**/*.test.ts"]`——留缝待裁决。
