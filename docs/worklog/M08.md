## [001] 2026-11-10 22:58 · M8-1～M8-6 · ComfyUI 生成后端六子任务一次完工

- **做了什么**：
  - M8-1 `registry.ts`：同步工厂 `createRegistry(dir)`，扫 dir 内 `*.json`；`nodes.length===0`/JSON 解析失败/kind 非法 → 拒绝入库；`requiresAdapter` 指向的文件不存在 → 注册但 `available:false` + reason（api-contract L863 VDN 语义）；hidden 照常入库。附 `CONTEXT_FRAMES = [5,22,39] as const` 常量导出（decision-log §12.2，M12 消费）。
  - M8-2 `client.ts`：`submit` POST /prompt → promptId（缺 prompt_id 报 comfy_offline 不猜）；**心跳只认 WebSocket /ws 的 progress/executing 事件**，`executing node=null` → done、`execution_error/execution_interrupted` → error；HEARTBEAT_TIMEOUT_MS（120s）无 ws 事件才判死，**全程不调 GET /history**（终态查询坑，architecture L1881-1884）；fetch/WS 均可注入（`fetchImpl`/`wsFactory`，测试零真实网络）。附 `free()`（/free）与 `deleteFromQueue`/`interrupt`（cancel 用）。
  - M8-3 `queue.ts`：cap=1 串行泵；出队前显存 < vramGuardMB → 挂起（suspended=true 轮询等空闲）；超 maxQueueLength → queue_full(503)；OOM → /free + 降档重试**一次**，第二次 OOM 原错上抛（comfy_out_of_memory 500）不静默降级；非 OOM 错误直接记录不重试。GPU 锁 holder 预留（`GpuLockHolder` 接口 + `setGpuLockHolder`，注释标明 M9 gpu/lock 就绪后对接，本轮不调用——G2）。任务失败统一记 `lastError()`（不静默）。
  - M8-4 `cancel.ts`：cancel = 本地队列移出（含守门等待中）+ unwatch（abort 轮询）+ 远端 queue delete + interrupt；幂等记忆 Set，重复取消返成功不抛、远端动作只做一次。
  - M8-5 `upscale.ts`：`assertReallyUpscaling(srcShortEdge, resolution)`——resolution ≤ 原短边抛 invalid_param，message 同时含两个数值（「目标短边不是倍率」坑，architecture L1250-1268）；`buildSeedVr2UpscaleWorkflow` 生成官方三件套（SeedVR2LoadDiTModel/SeedVR2LoadVAEModel/SeedVR2VideoUpscaler），静态图参数照抄实测表（batch_size=1、offload_device=cpu、cache_model=true+cpu、tiled 编解码、color_correction=lab、seed=42）；断言不过不发 /prompt。
  - M8-6 `openai.ts`：`createOpenAiRouter(deps)` 返回 express.Router（挂载归主会话，本轮不碰 server.ts）。`/v1/models` 只列 available、hidden 默认不出现 `?all=1` 展开、缺 adapter 的剔除；`/v1/images/generations` 返回 `{created, data:[{url}]}`；`/v1/videos` 返回任务制形状（id/object/status/created_at/model/metadata，含 deriveTaskType 推导回显 + promptShell + secondsToFrames 帧数），durationSec 限 5–15 整数秒超出 400 不封顶，显式 taskType 与素材冲突 → invalid_task_type_for_media 不静默改路；`/v1/videos/:id` 三态同形状，completed 附 url。失败统一 `{error:{message,type:"invalid_request_error",code}}`。**全部响应不套 {ok,data} 包络**。
  - 测试 `apps/core/test/comfy.test.ts`：31 例，spec §2.3 三个 ★ 用例全写死（见下）。

- **关键决定**：
  1. registry 用 node:fs 同步 API 扫描——spec 冻结的 `createRegistry(dir)`/`list()`/`get()` 全是同步签名，异步 IO 塞不进去；备选（惰性异步装载 + Promise 缓存）会改冻结签名，弃。
  2. id 解析：文件内 `id` 字段优先，缺省回退文件名去后缀（M07 pickWorkflowFile 的三份 h3 文件名与 registry id 并不一致，不能只认文件名）。
  3. queue 的 `waiting` 集合语义 =「已入队但尚未通过显存守门」：出队不删、守门通过/取消才删——守门循环靠它感知挂起期间的取消（vram_insufficient）。enqueue 全部后台泵（挂起等待是常态，不能卡提交方），错误经 `lastError()` 观察，Task.error 字段接线归主会话收尾。
  4. openai 错误 type 固定 "invalid_request_error"、code 用 DramaError code 透传；http 状态码取 `DramaError.http`（api-contract §7 只锁 JSON 形状）。
