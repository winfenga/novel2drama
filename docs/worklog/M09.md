- **关键决定**：
  1. **锁的互斥按 holder 类别**：同 holder 重入放行——TTS 持锁段（load→batch→unload）内 client.load() 幂等重入不能自我 409；跨类（tts↔comfyui↔video2x）严格互斥。备选「严格单次 acquire」会把幂等 load 场景弄死锁，弃。
  2. **冲突即 409 不排队**：spec 红线是「不静默降级」，排队策略归 M8 queue（G2：M9 建锁、M8 留接口注释、主会话收尾接线），锁层不做 promise 链。
  3. **容错匹配用自建莱文斯坦 DP** 而非引依赖：窗口 ≤ 数十字，O(mn) 无性能问题；阈值 max(1, len×15%) 向下取整保底 1（DEC §13.3 原式）。
  4. **G4 落法**：DEC §13.4 的 target_not_found / ambiguous_multiple_exact_targets 等状态语义进 DramaError invalid_param 的 `details.kind`，不照抄上游字段名；`is_not_a_speech_classifier` 语义（不拿能量当语音判据）在 M9 无能量检测面，不引入假实现。
  5. **繁简映射表手写 ~190 字** 不引 opencc：测试样本覆盖的实测字（漸/為/於/時…）全录；表可追加，注释声明「按需追加不删」。
  6. batch 的锁校验放 batch 层（status().holder==="tts"）而非抢锁：锁的持有段语义是「load→batch→unload 一整段」，batch 不能中途 release 再 acquire（会被 ComfyUI 插队）。
- **踩到的坑**：
  1. JS 无 `String.casefold`（那是 Python，DEC §13.1 的 normalized_asr_units 是 Python 代码）——TS 等价物 `toLowerCase`，首跑即抛 TypeError，已修。
  2. ASR token 会把标点粘在字上（实测「深,」）——spreadTokens 若不先 normalizeCjk 会把逗号当字参与匹配对齐；修法：token 先归一化再按空格切段拆字，标点剥离后余字均摊原 token 区间（近似均分，实测数据下逐位吻合）。
  3. vitest 的 mock child_process 里 stdout/stderr 共用一个 emit 频道会把同一块 buffer 喂两个监听器（帧号翻倍 0,100,0,100）；频道按 `stdout-data`/`stderr-data` 分离后修复。
  4. `pnpm -r exec tsc --noEmit` 全仓 1 error：`apps/core/test/comfy.test.ts(29,33) TS1005`——**归属 M8 轨**（该文件是 M8 并行施工中间态：`"...upscale.ts".replace(...) as never`、`await0()` 均为残缺占位）。M9 自有文件零 error（`npx tsc --noEmit -p apps/core` 过滤验证 + packages/shared tsc exit 0）。
