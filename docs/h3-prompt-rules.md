## 〇、先说结论

这份资料讲的是**一个 agent 怎么手写 H3 提示词**，不是 H3 引擎本身的规范。对我们项目，它提供三类东西：

| 类 | 内容 | 用法 |
|---|---|---|
| **A 校验口径** | 六段壳字段、枚举值、编号规则、禁写清单 | 直接变成我们的 schema 与出稿前校验 |
| **B 设计话术** | 反推引擎、运镜六条、位移三要素、台词配额 | 变成 LLM 的 system prompt 素材 |
| **C 踩坑记录** | 朝向、孤立 CR、保真重描、POV 误写转身 | 变成自检项，也是我们产品的卖点 |

**不适用的部分**：阶段 A/B/C（写小说）、阶段 F（K2 出图）、R18 内容规范大部分（除非我们要做同赛道）。

## 一、四条分支与六种 task_type 的对应

### 1.1 路由判定（`SKILL.md` §E1）

原资料的判定顺序：

```
① 是不是多参考连续链？
   ├─ 第 1 条 → Ref2VA
   └─ 第 2 条起 → Hybrid（接上一条实产尾帧当 first_frame）
② 有没有视觉素材？
   └─ 没有 → T2VA
③ 那张图是不是 0.00 秒首帧？
   ├─ 是，且没有其他素材 → I2VA
   └─ 是，且另有参考素材 → Hybrid
④ 图只作参考（人物/服装/场景/姿态/构图），或用多张图 → Ref2VA
⑤ 判不出来 → 兜底 T2VA
```

**与 `conditioning.py` 的对齐**（我们之前从代码推的 6 个 `task_type`）：

| 资料分支 | `task_type` | 成立条件 |
|---|---|---|
| T2VA | `t2va` | 零视觉素材 |
| I2VA | `i2va` | 单图，即首帧，无其他素材 |
| Ref2VA | `ref2va` | 一张或多张参考图，**无关键帧**，可带音/视频 |
| Hybrid | `hybrid` | **关键帧 ≥1 且 参考素材 ≥1** |
| （Ref2VA 变体） | `l2va` | 末帧锚定 |
| （Ref2VA 变体） | `fl2va` | 首帧+末帧 |

**注意**：资料只谈四条「输出壳」，`l2va` / `fl2va` 在资料里是「Ref2VA 挂了关键帧锚点」的处理，不是独立壳。`conditioning.py` 把它们拆成独立 `task_type`，是引擎侧的细分。

### 1.2 不可协商的例外（`SKILL.md` §E1 末尾）

> **素材里带了音频或视频参考时，只能走 Ref2VA 或 Hybrid** —— I2VA 与 T2VA 的壳里都没有 `<Audio N>` / `<Video N>` 的位置。

若同时还有明确关键帧 → Hybrid；没有关键帧 → Ref2VA。

**这条要写进我们的路由函数**：`if has_audio_or_video_refs and task_type in {t2va, i2va}: reject with reason`，引导改路，不静默降级。

### 1.3 Hybrid 成立条件（`hybrid-rules.md` §5）

| 项 | I2VA | Hybrid | Ref2VA |
|---|---|---|---|
| 关键帧 | 必须有（＝唯一那张图） | **必须有 ≥1** | 可选 |
| 参考素材 | **不得有** | **必须有 ≥1** | 必须有 ≥1 |
| 输出壳 | 指令行 ＋ 3 字段 | **六段** | 六段 |
| 关键帧标识 | 隐含为唯一图 | **`first_frame` / `last_frame` 字段名，不占 `<Picture N>` 号** | `<Picture N>`（占号） |
| `<Picture 1>` 是什么 | （无） | **第一张参考图**（关键帧不占号，故恒为 P1） | 第一张参考图 |

> **I2VA 是 Hybrid 的退化形态**：只有首帧、没有任何其他参考素材时 Hybrid 不成立，退成 I2VA。反过来，**I2VA 的任务一旦补上参考素材，就应当改走 Hybrid**（壳也随之从三字段换成六段）。

### 1.4 只给一类素材时（`hybrid-rules.md` §4）

点名 Hybrid 但只给一类：

- **只给关键帧** → 实际等于 **I2VA**（首帧）或首尾帧锚定，**没有任何参考素材**，人物身份只能靠这张关键帧自己锁
- **只给参考素材** → 实际等于 **Ref2VA**，**没有关键帧**，视频第一帧由参考图生成、**不保证**与任何一张图逐像素对齐

处理：① 说明冲突与代价 → ② 给两个可执行选项（补素材 / 降级，注意壳会变）→ ③ 等确认。

## 二、六段壳（Ref2VA / Hybrid 共用）

### 2.1 完整骨架（`ref2va-rules.md` §2）

> ⚠️ **下面这个骨架来自 `ref2va-rules.md`，是纯 Ref2VA 场景——没有关键帧。**
> 所以 `<Picture 2>` 是**第二张参考图**，不是首帧。
>
> **Hybrid 场景（有首帧）不要照抄这段编号**。Hybrid 里首帧用 `first_frame` 字段名标识，**不占 `<Picture N>` 号**，
> 编号从第一张参考图重新起 `P1`（见 §1.3 与 §2.5）。混用会导致 `<Picture 1>` 指向错误素材。

```text
subject_definitions:
<Subject 1>: ……人物身份与外观来自 <Picture 1>……
<Picture 2>: [Shot 1] 的第二张参考图（无关键帧，此处不写首帧）……

summary:
[reference generation] ……

retention_analysis:
<Subject 1>（出现在 [Shot 1]）: fully_preserved - ……
<Picture 2>（[Shot 1] 参考图）: fully_preserved - ……

detailed_description:
目标视频采用真人电影风格，……
[Shot 1] 画面从 <Picture 1> 开始，……

overall_soundscape: ……

non_diegetic_music: N/A

No subtitles, no watermarks, no additional on-screen text, no extra characters entering the frame.
```

**字段名与顺序不得变动。**

#### 2.1.1 Hybrid 版骨架（有首帧，与上面不同）

Hybrid 有首帧时，**首帧不进 `subject_definitions` 的 `<Picture N>` 行**，改用反引号字段名：

```text
subject_definitions:
<Subject 1>: ……人物身份与外观来自 <Picture 1>……
`first_frame`: [Shot 1] 的首帧，取景与构图以此为准。

summary:
[reference generation] ……

retention_analysis:
<Subject 1>（出现在 [Shot 1]）: fully_preserved - ……
`first_frame`: fully_preserved - ……

detailed_description:
目标视频采用真人电影风格，……
[Shot 1] 画面从 `first_frame` 开始，……
```

**两处差异**：
1. `first_frame` / `last_frame` 加反引号，**不加 `<Picture N>` 前缀**
2. `<Picture 1>` **恒为第一张参考图**，不被关键帧挤占

**验证**：`conditioning.py` 的编号逻辑里，关键帧字段独立解析，不参与 `<Picture N>` 的计数。这是引擎行为，不是文档约定。

### 2.2 三字段壳（T2VA / I2VA）

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

- **第一行是指令行**：I2VA 有，T2VA **没有**
- 指令行之后空一行，再写字段
- 「在 0.00 秒时 `<Picture 1>` 被完整参考」—— 这是 I2VA 的固定写法，逐字使用

### 2.3 枚举值全集（可直接做 schema）

| 类别 | 取值 | 备注 |
|---|---|---|
| **视觉保留** | `fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference` | |
| **音频保留** | `fully_copy` / `partially_copy` / `reference` / `weak_reference` | |
| **summary 任务类型** | `keyframe completion` / `reference generation` / `video editing` / `video continuation` / `audio reuse` / `audio reference` | |

**两处资料自己的收紧**：

1. `audio reuse` 在「只收人物声线」的前提下**不成立** —— 音频相关前缀只用 `audio reference`
2. `<Audio N>` 在 `retention_analysis` 里**一律写 `reference`**（最多到 `weak_reference`），**不写** `fully_copy` / `partially_copy`

**我们的选择**：这两条收紧**不必强制**。我们不做「只收声线」的限制，`audio reuse` 应当保留。但 `<Audio N>` 的默认值建议也从 `reference` 起。

#### 2.3.1 `audio reuse` 与 `audio reference` 的语义分工（2026-11-10 定案）

> 这两项资料口径不一：一处说「只收声线所以只能用 `audio reference`」，一处列了六个值含 `audio reuse`。
> **裁决：两个都保留，按「要不要原音频波形」区分。**

| 值 | 语义 | 用在什么时候 | `<Audio N>` 保留度 |
|---|---|---|---|
| **`audio reuse`** | **原样搬用**这段音频，波形不改 | 台词是剧本原句、情绪语气都对，只是视觉重拍 | `fully_copy` 或 `partially_copy` |
| **`audio reference`** | **只借声线特征**（音色、语速、口音），内容重念 | 同一角色说**新的**台词，靠参考音频锁音色 | `reference`，最多 `weak_reference` |

**判据一句话**：**声音内容换不换？**
- 不换 → `audio reuse`
- 换了 → `audio reference`

**我们的实际用法**：

| 场景 | 用哪个 | 为什么 |
|---|---|---|
| 单角色对白，剧本没改 | `audio reuse` | 配音一次成型，重拍画面不重配 |
| 同角色新台词 | `audio reference` | 音色要一致，内容必须新生成 |
| 多角色对话 | 每角色一条 `<Audio N>`，各用 `audio reference` | 声线分开锁 |

**为什么不能只用 `audio reference`**：那样会逼着所有镜头都重跑 TTS，而用户明确要「整句配音后按 ASR 切」——**切出来的片段本来就是原音频**，硬标成 `reference` 与事实不符。

**为什么不能只用 `audio reuse`**：新台词没有原音频可搬，只能靠参考。

**落到代码**：`AudioRef.retention` 枚举保留六个值不改，但**GUI 只让用户选这两个前缀**（`audio reuse` / `audio reference`），其余四个是 `retention_analysis` 内部字段，不是用户选项。

### 2.4 `<Picture N>` 何时单独定义（`ref2va-rules.md` §3）

> `<Picture N>` 只在它作为**首帧、关键帧、末帧或分镜锚点**时才单独定义。纯粹用来提供人物或服装的图片**挂在 `<Subject N>` 名下，不需要单独一行**。

**这条解释了 Hybrid 编号规则的由来**：关键帧用 `first_frame` / `last_frame` 字段名独立标识、**不占 `<Picture N>` 号**，所以 `<Picture 1>` 恒为第一张参考图。

只有一张纯人物参考图时的推荐结构：

```text
subject_definitions:
<Subject 1> is the adult woman whose face and black updo come from <Picture 1>.
```

不另写 `<Picture 1>` 行的关键帧定义；`summary` 用 `[reference generation]`；`retention_analysis` 只评估 `<Subject 1>`。

### 2.5 Hybrid 关键帧写法（`hybrid-rules.md` §2、§6）

**术语硬性**：关键帧英文**必须用工作流字段名** —— `first_frame` / `last_frame`（带下划线、反引号包裹）。

- 不得写成空格版 `first frame` / `last frame`
- 不得只写中文「首帧／末帧」而不给字段名
- 工作流节点（`first_frame` / `last_frame` 单选项）就是按这两个名字识别的

**编号契约**：

- 关键帧用字段名独立标识，**不占 `<Picture N>` 号**
- `<Picture N>` 从 1 起、按用户给图顺序连续编号
- 编号总数 = 用户本次给的关键图张数
- `<Audio N>` / `<Video N>` **不被关键帧挤位**，仍从 1 起
- 身份锚点绑在参考图（`<Picture N>`）上，**不绑在关键帧上**
- 关键帧**不被写成 `<Subject N>`**，也不在关键帧那一行塞声线或性格

## 三、三条链上铁律

这三个规则在资料里被反复强调，是整份文档最核心的设计。

### 3.1 之一：多参考必须走连续链

> **用户选用「多参考」（提供参考素材，需产出多条片段）时 —— 第一条用 Ref2VA，从第二条起一律采用 Hybrid。**

**理由**：纯 Ref2VA 的每一条都是各自独立生成，第一帧由参考图重新生成，**不保证与上一条的实产尾帧对齐** —— 人物姿势、朝向、位置、光线、道具持握全都会漂。

**尾帧来源纪律**：关键帧**只能用用户本条实际上传的图**。用户没给尾帧时主动问一句，并说明**不接就断链**。

### 3.2 之二：连续链必须逐条串行出词

> **Hybrid 分支（以及整条连续链）必须一段一段出。出完 01 就停下，等用户把 01 的实产尾帧图交回来，再用它当 02 的 `first_frame` 接着出 02。**

**理由**：

> Hybrid 的价值全在 `first_frame` 是**真实存在的实产尾帧**。猜出来的关键帧比没有更坏 —— 它会写进 `retention_analysis` 和 `[Shot 1]` 锚点句，让模型以为要逐像素复现一张并不存在的图，结果是既没接上前一条、又锁错了构图。

**用户催「一起给」时**：说明代价，给两个选项 —— ①按串行逐条来（推荐）；②确实要批量，则后续条目按**纯 Ref2VA** 出（不接帧）。

**用户已经一次性把尾帧全给了**（罕见）→ 不是串行了，正常逐条出，但**仍逐条落盘**。

### 3.3 之三：锚定首帧的条目开场不得静态停留

> **从 0.00 秒到本场第一个剧情节拍启动，不得超过 0.5 秒。**

**适用范围**：任何以某张图作为目标视频 0.00 秒首帧的分支 —— `I2VA`、`Hybrid`（`first_frame`）；`Ref2VA` 挂了首帧锚点时同理。**T2VA 无首帧，不受限。**

**理由（这是连贯性规则，不是节奏审美）**：

> 这类条目的首帧**通常就是上一条的实产尾帧**，而上一条的末帧**正处在运动之中**。本条开头若定格／静止片刻再动，等于在**上一条的运动中途硬插进一段静止** —— 接缝处顿一下，前后立刻显出「两段」的拼接感。
>
> 次要理由：景别、机位、姿态、服装状态、道具持握这些事实已由那一帧交代完，视频里再「摆」一遍就是白送时间。

**0.5 秒是上限，不是目标值** —— 越短越好，理想是首帧一挂上剧情就已经在走。

**节奏覆盖表**：

| 时长 | 通用节奏 | **锚定首帧覆盖后** |
|---|---|---|
| 5s | 铺垫 0–1.5 → 转变 1.5–3 → 高潮 3–5 | **铺垫 0–0.5 → 转变 0.5–2.5 → 高潮 2.5–5** |
| 7s / 10s / 15s | 建立段 0–2 / 0–2.5 / 0–3 | **建立段一律压到 0–0.5 秒**，其余阶段按剩余时长等比铺开，结尾仍留 0.4–0.8 秒余韵 |

**禁写清单**（中英文皆禁）：

| 禁用意思 | 英文禁用写法 |
|---|---|
| 镜头在首帧上停留片刻 | `the camera holds still on the image`、`the frame holds`、`holds on the opening frame` |
| 静置 / 定格一秒后再动 | `remains motionless`、`freezes for a moment`、`stays still before` |
| 先展示画面再开始动作 | `a brief pause before the action`、`the shot lingers`、`slowly comes to life` |

> **抬眼、呼吸、视线移动不算剧情节拍**，不能拿来充当开场动作。

**锚点句写法**：

```text
opens exactly on the first_frame image; the motion carried in from the previous clip continues without any hold, and her <本场第一个剧情节拍> is already underway within the first 0.5 second.
```

不许只写 `opens exactly on the first_frame image` 就转去描写静止画面细节 —— **那等于给模型发了一张「先停一下」的许可**。

**与尾帧的配合**：压掉开头铺垫**不减少剧情节拍** —— 塞不下照样按「① 加时长 → ② 拆条 → ③ 绝不删节拍」处理。**压缩的是接缝处的静止，不是剧情。**

**唯一例外**：用户明确要求「先定格 X 秒再动」→ 先说明接缝会顿的代价，再按其要求执行，并在文件头注明。

### 3.4 三条的分工

| 铁律 | 管什么 |
|---|---|
| 之一 · 多参考必须走连续链 | **帧接不接得上** |
| 之二 · 连续链必须逐条串行出词 | **关键帧是不是真的** |
| 之三 · 锚定首帧的条目开场不得静态停留 | **接上之后不许停** |

**三条都在服务同一件事：让 N 条片段看起来是一条。**

> **与本项目的冲突点**：我们前面定的「接帧是可选项，做成按钮，默认关」。**这三条铁律说的正好相反** —— 多片段场景下，接帧是默认、必须、串行。
>
> **本鲸的判断**：用户的按钮设计没错，但**默认值要多想一层**。建议：单条生成时按钮默认关（不受影响）；**一次生成多条时，第 2 条起默认勾上接帧**，用户可取消，取消时提示「不接会断链」。这不是违背用户决定，是补上他没考虑到的场景。

## 四、`<Audio N>` / `<Video N>` 规则

### 4.1 编号纪律（`ref2va-rules.md` §3.5）

- `<Video N>` 与 `<Audio N>` **各自独立编号**，编号不编码两者的配对关系
- 参考视频**不会**因为「文件里有声音」就自动产生 `<Audio N>`
- `(Sx)` 按目标视频里**实际发声顺序**分配一次，`<Audio N>` 的定义只是**复用**该 ID，**不得独立重新分配或编号**

**总上限**（资料自律）：`<Audio N>` 最多 3 条（N=1–3），每条 2–15 秒，**音频不能作为唯一参考输入**。

> 资料明确标注：官方 Ref2VA 规范文本**未给出数量上限**。这条是分镜类技能 `h3-prompt` 的本地约定。

### 4.2 `<Video N>` 只标结构不标内容

- 直接剪辑源视频 → `video editing`
- 从源视频结尾续写 → `video continuation`
- 参考运镜、切点、节奏或整体时间结构 → `reference generation`

> 参考视频里的**人、动物、物件、场景、动作、特效**如果被复用到目标视频，仍归 `<Subject N>`；`<Video N>` 只标识「资产来源或结构来源」，**不替代 subject 标签**。

### 4.3 `<Audio N>` 在六段里的落点

- **`subject_definitions`**：单独一行，说明这段声线属于谁
- **`summary`**：音频相关前缀用 `+ audio reference`
- **`retention_analysis`**：每个 `<Audio N>` 单独一行，**本节内不写 `(Sx)`**
- **`detailed_description`**：在该说话人**真正生效的那个镜头或语义阶段**引用，写明 `used as a voice-timbre reference`
- **不落进** `overall_soundscape` 或 `non_diegetic_music`

## 五、共用规则（`nsfw-template.md`）

四条件壳**仅输出结构与参考归因方式不同**；故事弧、动作库、运镜、位移、台词、音色、soundscape / music 规则**完全共用**。

### 5.1 运镜六条

1. **起点锚定（唯一硬规则）**：运镜必须从**参考图机位**出发。禁止方向冲突 —— 俯拍起点不升镜、仰拍起点不降镜、背面起点不正面直推、远景起点不切特写开场
2. **一条主运镜**：全片一条主运镜（缓慢推近最常用），至多叠加一个次运镜
3. **运镜跟随故事弧**：铺垫段镜头稳、转变段开始动、高潮段最近或定格；每次变化对应故事弧转折
4. **镜头-动作同步**：写镜头运动的句子必须同时写人物在同一时间在做什么
5. **三问（不是查表）**：展示方向朝哪 → 镜头往哪靠近；高潮落点在哪 → 终点停哪；参考图机位允许的合法运动方向是什么
6. **官方词表**：`Zoom In/Out`、`Push In/Pull Out`、`Pan Left/Right`、`Truck Left/Right`、`Tilt Up/Down`、`Pedestal Up/Down`、`Arc Shot`、`Tracking Shot`、`Static Shot`、`Shake Slightly/Strongly`、`POV`、`Roll Clockwise/Counterclockwise`，按需加 `with small/large amplitude`、`at slow/fast speed`

> ⚠️ **`Arc Shot` 使用裁决**（2026-11-10 定，解决「一处允许一处禁用」的冲突）
>
> 来源冲突：`nsfw-template.md` / 本文件 §5.3 用它做 POV 进场；v9.0 分镜总控则写「MiniMax **禁环绕运镜**」并要求拆成 `truck` + `pan`。
>
> **裁决 —— 按用途分，不是一刀切：**
>
> | 用途 | 允许？ | 条件 |
> |---|---|---|
> | **POV 进场**（§5.3 那条复合运镜） | ✅ 允许 | 必须慢速（`at slow speed`），必须带终点落点（`POV`），片中只此一次 |
> | 单纯绕着人物转圈当主运镜 | ⚠️ 谨慎 | 只在**静态或微动态**镜头用；幅度 `small amplitude` |
> | **动作镜头 / 打斗 / 快速位移** | ❌ 禁止 | 拆成 `Truck Left/Right` + `Pan Left/Right`，两段分开写 |
> | **人物入远景 / 大全景** | ❌ 禁止 | v9.0 明令：人物不入远景大全景 |
>
> **为什么**：H3 在 15 秒里处理持续旋转时，人物容易变形、背景容易糊。慢速小幅度转半圈能撑住，快速大范围环绕会崩。这不是文档矛盾，是**同一条物理限制在不同用途下的不同表现**。
>
> **状态**：裁决依据是文档推理 + H3 时长特性，**尚未逐条实测**。待第一轮出片后回头对账（见 `冲突对照表.md` 冲突 5）。

**禁止**：运镜编号、技术参数（速度数值、厘米、角度值）、「电影感运镜」式空话。

### 5.2 运镜描写纪律：只写「摄像机移动」（`nsfw-template.md` §7.5.6，实战固化）

**画面里出现的一切变化，必须归因于「摄像机移动」—— 不得写成「人物移动」或「场景移动」。**

用户实战原话：「是摄像机移动，并不是人物移动跟场景移动。」

1. **先声明不动的部分**：`the camera is the only thing that travels in this clip` + `every change that becomes visible in the frame is produced by the camera moving and by nothing else`
2. **画面变化必须带摄像机归因**：写「他的身体移到画面下缘」时必须写出**原因** —— `only because the camera now sits above his chest looking down the length of his body`。**不带归因的取景结果陈述会被读成人物自己在位移**
3. **人物只允许「姿态变化」**：俯身→直起、坐→跪、仰→侧，须与运镜句分开写，注明 `her own posture changing and not a move across the room`
4. **绕行／升降运镜下禁止声明全局左右轴**：`frame left and frame right never flip` 这类句子只在固定机位成立；摄像机一旦绕行，画面左右必然随之旋转 —— **强求左右不变，等于要求场景跟着摄像机转**
5. **绕行之后不得再按画面方位写光**：光源在房间里的位置不变，但在画面里的方位会随摄像机旋转；只写 `the window light`，不写 `the light from the left of the frame`
6. **POV 落到谁的眼位，摄像机就在谁的头／眼处**

### 5.3 POV 运镜（`nsfw-template.md` §7.5.5）

从参考图机位切到某角色第一人称，用**一条复合主运镜**，不切镜头、不换机位：

1. 起点必须是参考图机位
2. 一条复合运镜：`Arc Shot`（绕向目标角色头部）＋ 同步升降（`Pedestal Up/Down` 到眼高），终点写 `POV`
3. 三件事：① 起点是参考图机位；② 终点是哪个角色的眼位；③ 到位后该角色的脸出画，只留身体在画面下缘
4. **不得为了迁就镜头而让人物转身**：第三人称机位下她背对镜头、切到 POV 后自然正对镜头 —— 这是**视角变化**，不是**人物转身**。同一条里不得再写转身动作
5. POV 下「她朝向镜头」＝「她面朝他」，是同一件事，不要重复声明成两个动作

### 5.4 位移三要素

**触发条件（唯一条件）**：故事弧中存在姿态/重心变化（坐→跪、站→俯身、躺→撑起）。原地小动作（揉乳、解扣、舔唇）**不触发**。

**写法（从→到）**：

- **骨盆**从哪里移到哪里（贴地→前送、下沉→翘起、侧倾→转正）
- **双腿**从什么配置变成什么配置（伸直并拢→屈膝打开、站立→跪地）
- **躯干**从什么角度变成什么角度（直立→前倾下压、端正→后仰）

**连续性**：上一秒还端坐、下一秒已躺平张开腿而中间没有下沉过程 = **姿态瞬移，禁止**。

**正确**：

> 她双手缓缓撑向身后的床面，重心后移，双膝顺着床面向两侧滑开，躯干随着手臂的支撑一点点后仰，骨盆轻轻前送，从端正的跪坐变成分腿后仰支撑。

**错误**：

> 她原本跪坐在床上，随后张开双腿躺下。（姿态瞬移，中间过程缺失）

### 5.5 人物朝向 Facing（硬性）

**实战教训**：不写朝向 ⇒ 模型逐镜随机站向，成片里人物一会儿朝左一会儿朝右，剪在一起接不上。

**朝向三要素，缺一不可**：

1. **相对镜头**：正面对镜 / 3⁄4 侧向 / 侧向 90° / 背对镜
2. **画框左右**：面朝画面左 / 面朝画面右（侧向时必须写）
3. **两人相对关系**：面对面 / 一前一后同向 / 背对背 / 一方在另一方背后

**写法**：紧随风格句之后写一条 `Facing:` 句，出场角色各写一句，主角在前：

```text
Facing: she has her back to the camera with her body angled frame left; he lies face-up, which is toward the camera.
```

**同条内不得无动机转向**；确实要转身必须写转身动作并把变化写进同一句。

**跨条必须接得上**：相邻条目的朝向要在 `承接 / 下接` 里对得上；同一场景保持固定的机位轴线与左右关系。

**反例**：只写 `she looks at him`，不写谁朝哪边 ⇒ 必出随机朝向。

### 5.6 台词配额

| 时长 | 最多台词 |
|---|---|
| 5s | 0–1 句（1 句为佳，1–1.5 秒能说完） |
| 6–8s | 1–2 句 |
| 9–12s | 2–3 句 |
| 13–15s | 3–4 句 |

**落点**：台词落在动作相对稳定的片段，不要在剧烈位移或高速律动的中途说 —— 身体大幅移动时顾不上清晰发音。

### 5.7 口型同步（强制，资料标注「待实测验证」）

三条硬规则：

1. **台词期间嘴必须张**：必须用 `her lips part and her jaw drops` 开头。只写 `her red lips part slightly` 作为表情是**禁止**的 —— 那是状态描述，不是发音动作
2. **下颌呼吸停顿与发音同步**：`Her jaw resets at the pause, her nostrils flare slightly as she takes a breath, then her jaw drops again as she continues: <d>[Chinese] ……</d>`
3. **无台词时嘴唇自然闭合**，禁止「欲言又止」式无意义嘴部动作（刻意的喘息半张唇不在此列）

**错误写法**：`Her red lips part slightly as she says: <d>[Chinese] ……想要吗？</d>`

**正确写法**：

```text
Her lips part and her jaw drops, and the young woman with a soft, clingy, smiling voice (S1) says: <d>[Chinese] ……想要吗？</d> Her jaw resets at the end of the line, her nostrils flaring slightly as she takes a breath.
```

> **资料自己标注了「待实测验证」** —— 这条是否真能改善口型，要我们跑了才知道。

### 5.8 `overall_soundscape` / `non_diegetic_music`

- **`overall_soundscape`**：1–4 句英文，概括环境声、动作声、非语言人声（呼吸、轻喘、呻吟、体液声）。**台词与唱词属于主体字段，此处一律不重复。** 仅当用户明确要求全片无声才写 `N/A`
- **`non_diegetic_music`**：1–3 句英文，只写乐器、速度、节奏、力度变化，**禁止抽象情绪词**（「梦幻的」「情欲的」不得用于配乐描述）；无配乐写 `N/A`
- **技术排除行**：`No subtitles, no watermarks, no additional on-screen text, no extra characters entering the frame.` 附在 `non_diegetic_music` 之后

### 5.9 台词标签

- 台词写在 `<d>[Chinese] ...</d>` 内，**逐字保留，不翻译**
- 说话人身份、动作、音色质感（英文）写在 `<d>` 外
- 画外音：`says in an off-screen voiceover` + `while her lips remain completely closed`
- 台词跨切镜：`<scenetrans>` + `continues seamlessly across the cut`
- 台词被视频结尾截断：`<cutoff>`

## 七、Qwen-Image-2.1 图生图指令增强器

资料里有一整套，来源是 `qwen-img-2-1-nsfw` 技能，2026-10-02 并入。**这套跟 H3 没关系，是出首帧用的。**

主目标引擎：**Qwen-Image-2.1 系图像编辑模型**（长自然语言指令友好），同时对 ComfyUI / NAI5 / K2 / 瑶光 / zimage 通用。

### 7.1 输出格式：两段式

```
正向提示词
```text
<改写后的正向指令，单段连续文本，无换行>

wh_ratio="16:9" ｜ ratio_follow=""
```

负面提示词
```text
<负面提示词，单段逗号分隔短语列表，无换行>
```
```

**设计意图**：正向与负面**物理分开**，是为了能分别点复制按钮、分别粘进下游引擎的正向框与负向框；画幅行放进正向块，是为了点一次复制就把指令与画幅参数一起带走。

**关键约束**：

- 两个代码块的语言标记**都必须是 `text`**
- 画幅行**只允许出现在正向块内部、作为块内最后一行**，与正文空一行
- 正向正文**单段连续文本、无换行**，不截断、不省略号
- 正向正文内**禁止出现任何分辨率或比例信息**（`2:3`、`16:9`、`2K`、`4K`）—— 比例只由画幅行承载
- 除两段外**不输出任何文字**

### 7.2 三字段（底层 JSON）

```json
{
  "rewritten_prompt": "...",
  "wh_ratio": "16:9",
  "ratio_follow": ""
}
```

**互斥规则**：`wh_ratio` 有值 → `ratio_follow` 必须 `""`；反之亦然。

> 注意：`i2i-enhancer-rules.md` §1 明确声明**它覆盖** base 规则里的 `## Output Format` 段 —— 实际交付用两段式，不是三字段 JSON。三字段只在内部推理时用。

### 7.3 双重语言决策（这个设计很讲究）

**（A）改写后提示词的描述正文语言** —— 双引号**外面**的部分：

| 用户指令语言 | 描述正文语言 |
|---|---|
| 中文 | 中文 |
| 英文 | 英文 |
| 其他任何语言（日/韩/法/西/泰…） | **英文** |

**（B）要渲染进图的文字语言** —— 双引号**里面**的部分，按优先级：

1. 用户给出确切文字 / 指明目标语言 → 照办
2. 图里已有文字 → 用**图上现有的主导语言**（哪怕指令是别的语言）
3. 都没有 → 用**用户指令本身的语言**，**不要强行改成英文**

**例子**：图是泰文的，指令是英文要求加个标题但没给具体文字 —— 渲染出来的文字必须是**泰文**，而周围描述仍是英文。

**补充两条**：

- 引号内文字必须**单语言**，不得中英混排，不得输出双语对照（除非用户明确要求）
- **体裁不改变语言**：搞「规格表 / 电影数据文档 / 分镜板 / 技术参数」的观感靠排版与字体，**不能靠把标签换成英文**

### 7.4 属性解耦总原则

> **只改用户点名的属性，把每项都推到明显、不容错认的程度，其余全部保持输入保真。**

两种对称的错误：

- **泄漏（Leakage）**：碰了用户没点名的地方（锐化导致重新调色、放大导致重新构图、改风格导致脸漂、换装丢了配饰、换背景「顺手」清理了没提到的东西）
- **欠编辑（Under-editing）**：输出让人误以为是没编辑的输入，因为改动施加得太轻

> **保真只锁内容，不锁编辑强度。** 辨识度靠明确写出哪些保持不变来买，不是靠把效果压回去。

### 7.5 一条反直觉但极重要的规则

> **说明「保持什么」时，不要重新描绘它。**
>
> 用类型、位置、角色来点名未改动的内容，并优先用一句笼统的保真条款，而不是逐帧描述。
> **你越具体地描述你想保住的东西，它越容易漂** —— 因为在模型眼里那仍然是生成指令。
>
> 只对你**真正要改**的东西写具体外观，或者当它是唯一能区分相似物的手段时才具体。

**这条可以直接搬到我们的分镜提示词规范**：`保留` 字段不要重描，写类型/位置/角色就够。

### 7.6 其它关键规则

- **身份是最难的不变量**：人脸身份、产品的确切设计/标记/数量、输入图的渲染介质（照片/动漫/插画/素描/3D/油画），除非用户明确要改，否则一律存活
- **身份来自参考图时，指那张图，不要用文字描述特征** —— 文字描述会让模型重新生成、把相似度弄坏
- **多图（N≥2）必须用 `<image1>` `<image2>` 标签**，禁止「图1 / 第一张图 / the first image / image A」
- **单图（N=1）不加标签**，自然指代（「图像」「图片中」「the image」）
- **必须明确每张图的角色**：哪张是画布（构图与未改动内容存活）、哪张提供素材
- **写成指令语气**（以操作开头），不用「禁止改变 X」这类否定句，改用「保持 X 与输入图完全一致」
- **图上文字是字面的**：凡是会在输出里出现的可读文字，**必须给出确切字符、加引号、一个不落**；给不出确切文字的就不该加

### 7.7 画幅判定（大表）

**先看用户有没有明说尺寸或比例**：

| 说法 | 比例 |
|---|---|
| 正方形 / 头像 / 专辑封面 | `1:1` |
| 横版 / 电脑壁纸 / 视频封面 / PPT / 幻灯片 | `16:9` |
| 竖版 / 手机壁纸 / Instagram story / Reels / 短视频封面 | `9:16` |
| 手机全面屏 / iPhone 屏幕 | `18:39` |
| 安卓全面屏 | `9:20` |
| 超宽 / 带鱼屏 | `7:3` |
| **电影画面 / cinematic / 宽银幕 / cinemascope** | **`21:9`** |
| 海报 | `2:3` |
| 证件照 / 小红书 | `3:4` |
| iPad 屏幕 / 平板 | `4:3` |
| 全景图 | `2:1` |
| 名片 | `9:5` |
| A4 | `5:7`（竖）/ `7:5`（横） |

**一条明确的纠正**：

> 「2K」「4K」「8K」是**画质描述词，不是画幅指标**。不管用户说 2K 还是 8K，**输出分辨率一律按 2K 级处理**。画幅仍由别的线索或输入图比例决定。

**没明说时的默认**：

- **单图编辑** → `ratio_follow = "<image1>"`（跟随输入图）
- **单图场景生成**（写真、cosplay、穿越）→ 不跟随，按场景语义给：Portrait/写真/半身 `2:3`；全身/户外 `3:4`；横向 `3:2`；无方向线索才跟随
- **多图编辑** → 先认**画布图**，`ratio_follow` 设为它

多图的画布对照：

| 编辑类型 | 画布 |
|---|---|
| 合成（把 A 放进 B） | 目标场景图 |
| 换脸 / 换头 | 身体图 |
| 换装 | 人物图 |
| 风格迁移 | 内容图（不是风格参考图） |
| 换背景 | 前景主体图 |
| 局部物件替换 | 被编辑的原图 |
| 场景生成（无画布，如合影） | 无画布，按语义给：合影 `3:2`；写真 `2:3`；海报 `2:3`；桌面壁纸 `16:9`；手机壁纸 `9:16` |

**扩图不跟随原比例**（扩图按定义就改变比例）：按延伸方向推断，通常估算增加 30%–50% 空间。

| 延伸方向 | 比例变化示例 |
|---|---|
| 只往左或只往右 | `1:1` → `3:2` |
| 左右都扩 | `1:1` → `16:9` 或 `2:1` |
| 只往上或只往下 | `1:1` → `2:3`；`16:9` → `4:3` |
| 上下都扩 | `1:1` → `9:16` |
| 四边全扩 | **保持原比例** |

### 7.8 负面提示词六类骨架

**写法硬约束**：

1. 短语列表：逗号分隔的名词/名词短语，**不是句子**，单段无换行
2. **同语言**：与正向保持一致
3. **不写否定词**：直接写 `多余手指`，**不要**写 `没有多余手指` —— 否定词会被模型当成正面语义
4. **不与正向重复**：负面只兜正向管不住的**崩坏面**
5. **按介质取词**：介质漂移类词必须与目标介质相反

| 类 | 用途 | 示例词 |
|---|---|---|
| ① 介质漂移 | 防跑成别的画风 | anime 任务：`3D渲染` `CG渲染` `写实摄影` `半写实` `欧美厚涂` `油画笔触` `写实皮肤纹理` `毛孔`；realistic 任务：`线条描边` `平涂色块` `卡通描边` `赛璐璐上色` `二次元` |
| ② 手部崩坏 | **最高频崩点** | `多余手指` `六指` `手指融合` `爪状手` `畸形手` `手部糊连` `断裂手指` `手掌穿模` `手部与身体黏连` |
| ③ 肢体结构 | 防多肢与穿模 | `多余肢体` `多余的手臂` `多余的腿` `肢体融合` `肢体穿插` `镜像错位` `缺失肢体` `断肢` |
| ④ 器官与接触 | 防器官错位 | `畸形生殖器` `器官错位` `器官缺失` `插入关系断裂` `接触点悬空` `色块界限错位` |
| ⑤ 面部与身份 | 防脸崩 | `面部崩坏` `换脸` `五官错位` `双眼不对称` `瞳孔异色` `脖子过长` `头身比失衡` `手过大` `肤色断层` |
| ⑥ 画面技术 | 防工程痕迹 | `低分辨率` `模糊` `噪点` `过度锐化` `锯齿` `拼接痕迹` `接缝` `色带` `水印` `签名` `文字` `logo` `边框` `黑边` |

**裁剪纪律**：

- SFW 任务：删掉 ④ 整类
- **构图已排除手部（手不入镜）：② 类保留** —— 它正是防手部误入镜的那道闸
- 器官局部特写：④ 类必须写满，补 `结构对称性错误` `解剖分界模糊`
- **六个类不必每类都出词，但至少要覆盖 ①③⑥**（介质漂移 + 肢体 + 工程痕迹是通用崩坏面）

## 八、对本项目的适配判断

这一节是**判断**，不是抄录。

### 8.1 建议直接采纳

| 项 | 理由 |
|---|---|
| 六段壳字段名 + 枚举值全集 | 直接做 schema |
| `<Picture N>` 只在关键帧时才单独定义 | 解释 Hybrid 编号由来，写进校验 |
| `first_frame` / `last_frame` 用字段名不占号 | 引擎实际按此识别，必须遵守 |
| 朝向三要素（Facing 句） | 产品级缺口，不写必出随机朝向 |
| 位移三要素（骨盆/双腿/躯干 从→到） | 防姿态瞬移 |
| 台词秒数配额表 | 做成 LLM 提示词约束 |
| 孤立 CR / 伪 `>` 行检查 | 程序生成 prompt 必查 |
| `overall_soundscape` 不重复台词 | 简单可校验 |
| `non_diegetic_music` 禁抽象情绪词 | 简单可校验 |
| 负面提示词不写否定词 | 若做提示词后处理必守 |
| 「保真别重描」原则 | 我们 `保留` 字段的规范 |
| 2K/4K 是画质不是画幅 | 画幅判定必守 |
| 运镜描写归因于摄像机 | 防「场景移动」误写 |

### 8.2 需要改写后采纳

| 项 | 原资料 | 我们的做法 |
|---|---|---|
| **接帧默认值** | 多片段第 2 条起**强制**接帧 | 按钮保留，但**一次生成多条时第 2 条起默认勾上**；取消时提示「不接会断链」 |
| **串行出词** | 一条一条出，出完停 | 我们的架构是**批量队列**，串行由队列保证。但**尾帧依赖要显式建模成任务依赖**，不能让第 2 条先跑 |
| 三条壳（T2VA/I2VA/Ref2VA/Hybrid） | 人为选 | 我们**按素材自动判**，判定不出才问；判定结果给用户看一眼可改 |
| `audio reuse` 禁用 | 只收人物声线 | 我们**不限制**用途，`audio reuse` 保留 |
| `<Audio N>` 保留值固定 `reference` | 只取音色 | 我们允许 `fully_copy` / `partially_copy` |

### 8.3 明确不做

| 项 | 理由 |
|---|---|
| 阶段 A/B/C 写小说 | 我们是文本转短剧，输入已是文本 |
| 阶段 F K2 出图 | 出图走我们自己的引擎链路 |
| R18 内容规范（动作库 / 尺度用语） | 用户没要求；若做同赛道可再议 |
| `audio reuse` / `video editing` 的完整语义 | 当前不做视频改写功能 |
| 口型同步三条硬规则 | 资料自己标「待实测验证」，先不写死 |

### 8.4 待用户确认

1. **接帧的默认值** —— 单条默认关是本鲸理解的；多条场景第 2 条起默认开，用户认不认？
2. **要不要暴露 R18 尺度** —— 资料里的动作库/台词规则如果不用，那 `nsfw-template.md` 的运镜与位移部分就是唯一有用的，其余可以整体跳过
3. **POV 运镜要不要支持** —— 它依赖复合运镜 + 角色眼位，实现成本不低
4. **口型同步规则要不要试** —— 需要跑一轮实测才知道有没有用
