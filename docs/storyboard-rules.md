## 〇、这份东西跟前面几份的区别

`r18-novel-h3` 那套是 **agent 手写 H3 提示词的操作手册**，只覆盖 H3 一个模型。

**v9.0 分镜总控是一套完整的分镜生产系统**，覆盖从剧本到多模型出词的全链路，而且里面有几条**我们方案里没有但确实需要**的东西：

| 我们缺的 | v9.0 怎么解 |
|---|---|
| **时长级联** —— 改一个镜头时长，牵连哪些东西？ | §6.2 给了 9 条公式，全部是 D 的函数 |
| **资产编号体系** —— 角色/场景/道具怎么全局唯一 | §5.1 `SC-01` / `CH-01` / `PR-01` + 状态变体 `SC-01-A/B` |
| **多模型适配层** —— 同一份分镜怎么喂不同模型 | §7 四个适配器（Seedance / H3 / MiniMax旧版 / 通用） |
| **质量门与风险打分** —— 出稿前怎么系统化查漏 | §10.1 20 项风险分，任一 2 分不许出片 |
| **因果网络审计** —— 动作有没有后果 | §10.2 反事实检验 |
| **台词字数预算** | §6.2 第 3 条：`字数 ≤ floor(D × 3)` |

**核心洞察**：

> **第一页一个时长变量控制全片所有分镜秒数**，同一套内部计划自动适配任意视频/图片生成模型。

这个「**规划与模型解耦**」的思路，正好对上主人说的「内置 MCP、云端和本地 AI 都能处理、不用管是不是云端」—— 内部只维护一份计划，输出时按目标模型渲染。

## 一、八条最高优先级铁律（PART 0.2）

原资料称「不可协商，任何指令冲突时以此为准」。**这八条我认为整套文档里最值钱的部分。**

| # | 铁律 | 内容 |
|---|---|---|
| **R1** | **事实铁律** | 可补充「美术细节」，**绝不补充「剧情事实」**。证据优先级：剧本原文 ＞ 原文直接推断 ＞ 合理美术补全。无证据的关键事实必须标 `【待确认】` |
| **R2** | **单点定义铁律** | 每个场景/人物/道具只有**一处唯一定义**；其余各处只引用编号、不复述、不改写 |
| **R3** | **从事实重建铁律** | 每个分镜开头必须**从规范事实重建「第 0 秒初始空间位置」**，不得沿用上一镜渲染结果（**防止漂移复合放大**） |
| **R4** | **所见即所得铁律** | 提示词只写镜头内**实际可见/可闻**的内容；心理活动、设定说明、镜头外事件不得写进「画面与动作」，只能进「情感解析 / 导演备注」 |
| **R5** | **时长闭合铁律** | 时间码必须连续、无缺口、无超帧，且 `end − start = 该镜生效时长`；内容必须演得完 |
| **R6** | **无字幕铁律（默认）** | 视频内不生成字幕、台词文字、水印、Logo、UI、编号、标签 |
| **R7** | **模型母语铁律** | 最终提示词必须渲染为目标模型的**原生格式与语言** |
| **R8** | **不完整不出片铁律** | 任一质量门未过，禁止进入下游、**禁止宣称完成** |

### 对本项目的判断

**R3 是本鲸之前完全没想到的**。它说的「漂移复合放大」正是接帧链最大的风险：如果第 2 条从第 1 条的**渲染帧**推断空间关系，第 3 条又从第 2 条的渲染帧推断，误差会一层层放大。v9.0 的解法是 —— **空间关系永远从事实台账（CF）重建，渲染帧只用来接画面**。

这跟我们「从原片（超分前）抽帧」是同一个思路，但更进一步：**帧只提供像素，位置信息从文本事实来**。

**R2 是资产一致性的根**。我们之前讨论角色一致性时想的是「参考图 + 特征描述」，v9.0 的做法是「唯一定义 + 全局编号 + 其余只引用」。配合 PART 5 的资产专区，等于把「描述」和「引用」彻底分开。

**R4 是最容易被 LLM 违反的一条**。LLM 天生爱写「她心里想着…」，进了视频提示词就是废字。这条必须做成硬校验。

**R8 是产品态度** —— 「不完整不出片」而不是「尽力而为」。我们方案里没这条，建议补上。

## 二、全局配置面板（PART 1）

### 2.1 六个变量区

```yaml
# ① 核心时长变量（最高杠杆）
GLOBAL_SEG_DURATION_SECONDS: 15      # 每个分镜目标秒数，常用 6/8/10/12/15/20/30
PER_SHOT_DURATION_OVERRIDE: {}       # 单镜覆盖，如 {"S03": 10, "S07": 8}

# ② 目标模型
TARGET_VIDEO_MODEL: "AUTO"
TARGET_IMAGE_MODEL: "GPT_IMAGE"

# ③ 题材与风格
GENRE_STYLE: "AUTO"
STYLE_INTENSITY: 1.0                 # 0.5 克制 ~ 1.5 浓烈
MASTER_STYLE_OVERRIDE: ""            # 非空时优先于题材库

# ④ 画幅与语言
ASPECT_RATIO: "16:9"
OUTPUT_LANGUAGE: "AUTO"              # AUTO | ZH | EN

# ⑤ 声音 / 音乐 / 字幕
BGM_POLICY: "POST"                   # POST(后期加，视频内无BGM，默认) | NATIVE | NONE
DIEGETIC_SOUND: "ON"
SUBTITLE: "OFF"

# ⑥ 镜头 / 连续性策略
SHOT_SIZE_POLICY: "STANDARD"         # STANDARD | CINEMATIC | VERTICAL_TIKTOK
MAX_FACES_VISIBLE: 3
CONTINUITY_REBUILD: "FROM_FACTS"     # 强制每段从事实重建，勿改
ONE_TAKE_PREFER: false
VFX_GRADE: "AUTO"                    # AUTO | S | A | B | NONE
NEGATIVE_PROMPT_LEVEL: "CORE"        # CORE | FULL
```

每次执行必须在**最开头**输出最终配置：

## 三、唯一内部表示（PART 2.2）

**规划与模型解耦的核心**：全流程只维护两份内部数据，所有模型输出都由它们「渲染」而来，**禁止为不同模型重写规划**。

### 3.1 规范事实台账 CF（Canonical Facts）

```
WORLD      世界观 / 规则 / 时代
STYLE      风格母版（风格逻辑 / 色调 / 光影）
SCENES[]   编号、名称、空间结构、固定陈设、出入口、时间/光影、状态变体
CHARACTERS[] 编号、角色定义栏（外貌/服装/身高/体型/妆容/发型/皮肤/配饰/声音锚点/性格/表演核心）
PROPS[]    编号、名称、形态、材质、状态变体、归属
```

**每条事实带 `EVID` 证据等级**：`原文` / `推断` / `补全` / `待确认`

### 3.2 规范镜头计划 CSP（Canonical Shot Plan）

```
SEG[]    编号、叙事目的、场景、登场人物、起止时间码、生效时长、节拍列表
SHOT[]   时间码、景别、运镜、初始站位、动作事件、表情变化、台词、
         环境互动、声音、物理反馈、情感解析、引用资产编号、风险分
```

### 3.3 两阶段流水线

```
原始剧本（任意形态）
   │ ── Phase A：剧本标准化（PART 3）
   ▼
规范事实台账 CF（唯一事实源）
   │ ── 风格/段落总控（PART 4/6）
   │ ── 全局素材专区·图片提示词（PART 5）
   ▼
规范镜头计划 CSP（含时长级联 / 9 槽预算 / 连续性）
   │ ── Phase B：模型适配（PART 7）
   ▼
目标模型「直给」视频提示词 + 图片素材提示词
   │ ── 质量门 / 因果审计（PART 10）→ 不达标回修
   ▼
按 PART 11 交付
```

**Phase A 默认内部执行、不单独输出**；用户要求透明时才给。

### 对本项目的判断

我们方案的领域模型里已经有 `SourceUnit` / `DialogueLine` / `VoiceProfile` / `Asset` / `Character`，但**没有 CF / CSP 这个分层**。

建议：

- **把现有实体归到 CF 层**（Character / Asset / VoiceProfile → CHARACTERS[] / PROPS[] + 声音锚点）
- **新增 CSP 层**（我们现在的 `Shot` 基本就是 CSP.SHOT，但缺 `EVID`、`初始站位`、`风险分`、`引用资产编号`）
- **证据等级 `EVID` 是个好东西** —— LLM 生成的设定哪些来自原文、哪些是它编的，用户有权知道

## 四、时长级联公式（PART 6.2）—— 最实用的部分

> **核心：改 D 必须重算一切。**

设某镜生效时长 `D = PER_SHOT_DURATION_OVERRIDE[Sn]`（若有）否则 `GLOBAL_SEG_DURATION_SECONDS`。

| # | 项 | 公式 |
|---|---|---|
| 1 | **时间码** | `start_n = Σ D(前序)`；`end_n = start_n + D`；全片连续、无缺口、无超帧 |
| 2 | **模型上限自动切分** | 目标模型单镜上限 `Mmax`。`D ≤ Mmax` 单镜；`D > Mmax` 切为 `k = ceil(D / Mmax)` 个子镜，尽量均分且各自 ≤ Mmax，子镜间动作匹配/顺接，时间码连续 |
| 3 | **台词预算** | 中文自然语速约 **3 字/秒**（留停顿）。单镜台词总字数上限 `≈ floor(D × 3)`，**建议值 `floor(D × 2.5)`**；超出则拆镜或精简 |
| 4 | **动作密度（9 槽预算）** | `slots = min(9, round(D × 0.6))`。D=15→9；D=10→6；D=6→4。一槽 = 一个主动作事件（谁→做什么→对谁→结果→必要物理/声音反馈） |
| 5 | **视觉节拍数** | 纯视觉/动作镜节拍 `≈ ceil(D / 4)`（每 3–5 秒一个核心事件）；反应拍/停顿计入 |
| 6 | **运镜预算** | 规划层每节拍 ≤ 1 个主运镜；**落到 H3 时整条只保留 1 条主运镜**。单镜复杂运镜 ≤ 2 |

> **运镜密集度定案**：
>
> 两处口径（H3提示词规则「全片一条」vs 本文档「每节拍一条」）说的是**不同层**，不是矛盾：
>
> | 层 | 规则 |
> |---|---|
> | **规划层（CSP）** | 每节拍 ≤ 1 个主运镜。一场戏可跨多个节拍，每节拍有自己的镜头意图 |
> | **渲染层（H3 单条）** | **整条只保留 1 条主运镜**，至多叠 1 个次运镜 |
>
> **理由**：H3 一条最长 15 秒，`ceil(15/4)=4` 个节拍。**让模型在一条 15 秒里执行 4 次运镜切换，必出抖动和漂移**。所以规划层的多运镜意图，在渲染时必须收敛成一条 —— 剩下的部分要么降为次运镜，要么拆条。
>
> **执行**：渲染时按「故事弧最重要那个节拍」选主运镜，其余节拍的运镜意图**丢弃或降级**，并在 `detailedDescription` 里用画面动作衔接代替运镜切换。
| 7 | **表情变化** | 单镜可见表情 1–3 个，按时间点标注；过密则删并 |
| 8 | **同镜人数** | 可见人脸 ≤ `MAX_FACES_VISIBLE`（默认 3） |
| 9 | **转场/声音点** | 转场只在镜间接缝；声音事件时间点与时间码对齐 |

> **以上所有量都是 D 的函数；改 D 后必须逐项重算并在交付中体现，禁止只改时间码尾数。**

### 对本项目的判断

**这段直接回答了我们方案里一个空白**：主人说过「台词时长和镜头时长是独立的，台词冗余很长的，不可能说视频 5.12s 台词就用 5.12」。v9.0 给的是**反过来的约束**：

- 镜头时长 D 是主变量
- 台词是 D 的**函数**：`字数 ≤ floor(D × 2.5)`
- 塞不下 → **拆镜**，不是压缩

**注意这跟主人之前的判断方向相反**。主人是「先有台词，再看需要多长镜头」；v9.0 是「先定镜头时长，台词必须塞进去」。

**本鲸的看法**：**两者都要支持，取决于入口**。

- 从**已有剧本**进来（我们的主场景）→ 台词是事实，镜头时长得迁就台词 → 主人那套对
- 从**分镜设计**进来（时长优先的创作模式）→ v9.0 那套对

所以这个公式的用法应该是：**当台词超预算时，提示用户「这个镜头按当前时长塞不下，要不要加长到 X 秒 / 拆成两镜」，而不是静默压缩台词**。

**9 槽预算 `min(9, round(D × 0.6))` 是个很聪明的启发式** —— 它防止一镜里塞太多动作。我们分镜里有「运动矢量」字段，可以挂到这个预算上校验。

## 五、资产编号体系（PART 5）—— 我们完全缺的

### 5.1 编号规则

| 类 | 格式 | 状态变体 |
|---|---|---|
| 场景 | `SC-01`、`SC-02`… | `SC-01-A`(白天)/`B`(黑夜)/`C`(损毁) |
| 人物 | `CH-01`… | 多状态（变身/龙化/离析前后）：`CH-01-A/B` |
| 道具 | `PR-01`… | 状态变体同理 |

**硬规则**：

- **一经分配永不改变**
- 素材图在视频模型中的引用编号与之一一对应（`@图片1 = CH-01`、`@图片2 = SC-03`）
- **同一张图在所有分镜中永远是同一个 `@图片号`**，在《全局资产引用对照表》中锁定
- 编号顺序：按**资产在分镜中首次出现顺序**分配；**先人物/场景，后道具**

### 5.2 单点定义纪律

> 本专区是全片**图片资产的唯一定义与派生处**。所有视频分镜**只引用这里的固定编号**，不在镜头内重新生成/描述资产。
>
> **视频一致性上限由素材图一致性决定。**

### 5.3 人物资产板（角色多视图 / 定妆照）

每个登场人物产出一张「角色主资产板」，用于锁定身份/体型/服装。三种等价模板：

**模板 A · GPT_IMAGE 真人定妆（观察者英文段 + wh_ratio）**

- 横向资产板，**左侧约 40%** 为正面头肩超高清特写（头摆正、双眼正视镜头），**右侧约 60%** 为同一人完整全身正面站姿 + 完整全身背面站姿
- 三视图/四视图必须为同一人，五官/发型/服装/身体比例完全一致
- 真人质感词：真实皮肤/毛孔/细茸毛/血色、真实发丝、真实布料纤维与材质反射；自然侧逆光 + 柔和轮廓光
- 禁塑料/蜡像/过度磨皮/网红写真/廉价滤镜

**模板 B · H3 六段式多视图板**

- 版面（写进 `<Subject 3>`）：四栏等宽等高、基线对齐、窄白间隙；第 1 栏头像栏（上正面头像 / 下四分之三侧头像），第 2–4 栏为正面/侧面/背面身体视图（**试装记录照**：颈线至足底、头部在画外，`f/8`、`1/125`、`ISO100`，固定机位）
- 影棚（`<Subject 2>`）：纯白连续背景墙；30–40° 柔主光 + 弱补光 + 侧后轮廓光
- `summary` 用 `[reference generation]`；`retention_analysis` 对各 Subject 标 `fully_preserved`（换装/改脸用 `partially_preserved` 并写明替换项）
- `detailed_description` 写**单 `[Shot 1]` 静止**、无运镜、无姿态变化；soundscape/music 写 `N/A`

> **资产板豁免「0.5 秒起步」铁律 —— 已定案。**
>
> `_原文摘录\07_hybrid-rules_全文.md` 的铁律要求：带首帧的条目 `0.5 秒内必须有剧情节拍`，禁写 `remains motionless`。
>
> **资产板不受这条约束**，理由：
> 1. 那条规则防的是**视频接缝处的静止**（上一条末帧在动，本条开头定格 ⇒ 顿一下）。**资产板是单帧静图，没有前后条，没有接缝。**
> 2. 铁律的适用范围原文写的是「**任何以某张图作为目标视频 0.00 秒首帧的分支**」—— 资产板根本不是「目标视频」。
>
> **实现**：资产板走**独立的 `still-frame` 模式**，不出视频。请求带 `kind: "portrait" | "asset-board"`，校验时跳过「0.5 秒起步」和「时长 5–15 秒」两项。

### 5.4 场景锚定图（主 + 辅 + 俯视平面图）

每个独立场景产出一张「场景锚定图」，作为**空间一致性最高杠杆资产**：

- **左侧约 60%**：主机位图，完整展示场景全貌、主要表演区与空间纵深
- **右上约 20%**：辅助机位图，补充另一角度/关键结构
- **右下约 20%**：**严格俯视平面调度图**，标明墙体/门窗/出入口/功能区/家具位置与朝向

**一致性铁律**：

- 主/辅/俯视必须是**同一个 3D 场景**，仅机位/视角不同
- **平面图是空间关系的唯一裁决**，视图 A/B 必须与平面图严格对应
- **空场景（无人物）**，仅固定陈设与道具
- 色彩/光影/质感**逐字沿用风格母版**

**这套资产编号是当前方案最大的缺口之一**。我们 `技术实现.md` §3.1 有 `Asset` 实体，但没有全局编号规则、没有状态变体、没有「@图片N ↔ 资产 ↔ 分镜」的对照表。

## 六、连续性与第 0 秒初始空间位置（PART 6.3）

> 每个分镜正文开头输出 `## 初始空间位置关系`：只写该镜**第 0 秒状态** —— 每个人/关键道具的方位、距离、朝向、姿态，以及固定场景锚点；用方位词（左/右/前/后/中央/门口/桌后）与必要的 **ASCII 站位图**。

**铁律**：

- 该初始位置**从 CF 事实与上一镜「结束状态」的事实结果重建**，**不沿用渲染帧**
- 上一镜结束位置 = 本镜开始位置（**事实层面**）
- 镜内所有位移必须可由初始位置连续推出
- **禁止人物/道具凭空换位、消失、出现**（必须给出方向、遮挡或起止状态）

### 镜头设计要素（PART 6.4）

- **景别**：远景（**仅空镜/环境建立**）、全景、中景、近景、特写；相邻镜避免同景别连续；**人物在 MiniMax 系不入远景/大全景**
- **运镜**：固定、推/拉、横移 truck、摇 pan/tilt、升降、跟拍、甩镜、焦点转移、手持；**MiniMax 系禁「环绕」，拆为 truck+pan**
- **动作写法**：写「动作段」**不写「人体运动学」** —— 只写 谁→做什么→对谁→结果→必要声音/物理反馈；一镜一核心事件
- **连续性连接词**：同时 / 紧接着 / 顺势 / 连续 / 刚…就… / 还没…已经…
- **禁空泛副词**：极具力量感地 / 帅气地 / 迅猛无比 / 如鬼魅
- **慢动作**：仅作时间标注（如「命中瞬间 0.3 秒慢放」），不写「唯美慢镜」等无法执行词

### 群像焦点纪律（PART 6.5）

- **当前焦点是谁就拍谁**：单人镜只描述该人；双人镜只描述这两人
- **镜外人物不写动作/不点名**，只写「看向画外某方向」或「传来画外音」
- 反应/表情只给当前在焦人物；群像背景人物保持合理静止/低干扰
- **对话过肩（OTS）遵循轴线（同场不越轴）**，过肩镜给「前景肩背（虚）+ 对方面部（实）」

### 对本项目的判断

**「初始空间位置关系」这个字段必须加进我们的分镜模型。** 它和 `ep01_storyboard.md` 里的「关系 `same_setup`」是互补的 —— 后者标的是「跟上一镜同一个物理设置」，前者给的是**具体坐标化的状态**。

**ASCII 站位图**也值得抄：文本比表格更能表达空间关系，而且 LLM 读得懂。

`nsfw-template.md` 的「朝向 Facing 三要素」和这里的「初始空间位置」合起来才是完整的空间控制：

- **Facing** 管「面朝哪个方向」
- **初始空间位置** 管「站在哪里」

### 8.2 因果网络审计（PART 10.2）

对每个分镜建立「动作—结果」因果网络：

**1. 节点**：本镜动作事件、被作用对象、场景/道具状态、可见表情、声音点、引用资产

**2. 边（必须可验证）**：`起点 → 中间节点 → 目标`、关联机制、影响方向/强度、时间点、证据、置信度

**3. 多跳追问**：

- 该动作的**直接结果**是否在镜内可见？其**间接结果/二阶影响**是否影响下一镜初始状态？
- 动作是否依赖某隐藏前提（道具在手/站位/能力条件/信念）？**前提是否在第 0 秒已成立？**
- 是否存在反馈/连锁（命中→形变→位移→碰撞→声音）？
- 跨域一致性：风格/色调/光影/材质是否与母版和素材图一致？
- 弱信号：视线/手势/声音方向是否与站位、轴线、@图片引用一致？

**4. 区分关系类型**：直接因果 / 间接因果 / 相关未证因果 / 共同原因的表面关联 / 推测性联系 / 待验证假设。**禁止为凑全面而牵强建立关联。**

**5. 反事实检验**：

> **若去掉该动作/该资产/该前提，镜头是否仍成立？若仍成立则为冗余，应删；若不成立则确认其必要性与可见性。**

### 8.3 质量门禁顺序

```
Phase A 事实门 → 风格/资产门 → 规划/时长门 → 适配门 → 成片总检
```

**修复闭环**：打分/审计 → 列出问题（定位到具体字段 + 风险等级 + 修复建议）→ 修复 → **重跑受影响的全部下游产物与全部相关检查（非仅改出错处）** → 重评，直至无 2 分。

### 8.4 成片总检清单（PART 10.4）

- [ ] 配置已回显；所有 AUTO 已判定
- [ ] 时长 D 级联正确：时间码、台词字数、9 槽、节拍、运镜、表情、子镜切分
- [ ] 每段从事实重建初始位置；站位/轴线/视线一致
- [ ] 资产单点定义、编号全局固定、@图片引用对照无误
- [ ] 场景/人物/道具图片提示词为目标图片模型正确语法（含 `wh_ratio`）
- [ ] 视频提示词为目标视频模型母语；负向/BGM/字幕策略正确
- [ ] 无镜头外/心理内容进入画面；无新增/改写剧情
- [ ] 因果网络审计无断链；风险无 2 分
- [ ] 交付项齐全、顺序正确

### 对本项目的判断

**20 项风险分可以直接变成我们的校验器**。尤其这几项我们方案里完全没有：

- **⑦ 初始位置未从事实重建** —— 接帧链最容易犯的错
- **⑧ 动作超 9 槽** —— 有量化标准，可自动查
- **⑨ 台词超字数** —— `floor(D × 2.5)`，可自动查
- **⑫ 状态变化缺起止锚点** —— 变身/消失/出现必须有起止双锚点
- **⑰ 出现镜头外/心理描写进画面** —— LLM 最常犯

**反事实检验**这条思路很妙：**如果一个动作删掉镜头依然成立，那它就是冗余的**。这比「检查有没有写全」更严格，能揪出堆砌型废话。

**「重跑全部下游产物，非仅改出错处」** 也是工程纪律 —— 改一个时长，所有依赖它的时间码、台词预算、9 槽预算都得重算。

## 九、交付规范（PART 11）

### 9.1 固定交付顺序

1. **【本次运行配置】** + **【待确认清单】**（若有）
2. **一、全片总控**：题材/风格母版三层；段落总表（编号/叙事目的/场景/人物/时长/时间码）；全片情绪/张力曲线
3. **二、全局素材专区**：人物资产、场景锚定图、道具多视图板提示词 + 《全局资产清单》《全局资产引用对照表》
4. **三、分镜提示词（模型直给）**：按目标适配器逐段输出
5. **四、声音与后期音乐说明**、**转场说明**
6. **五、质量与审计**：风险打分汇总、《分镜因果网络审计表》、修复记录、成片总检结论

### 9.2 输出纪律

- 成品**可直接复制投喂**：每个分镜/每段素材提示词独立成块、边界清晰、编号一致
- **不输出内部思维链**；不夹带与本片无关的模板说明
- 模板占位符必须替换为实际内容或**显式标注待确认**
- 语言：最终提示词跟随目标模型；交付说明跟随用户语言
- 剧本过长可按「场景/章节」分批交付，**每批内部完整闭环**，并保持**资产编号与时间码全局连续**

## 十、专业模块（PART 8）—— 按题材条件加载

### 10.1 动作戏模块

- **打击感物理**：A1 帧停（命中瞬间断句/停一拍再砸下）、A2 惯性延续（收不住/滑行/犁沟/砸穿）、A3 重量感（地裂/震尘/肌肉蓄力）、A4 受力形变（脸揍歪/盾凹拳印/墙嵌人形）、A5 力的传导（表面不破内部碎/隔物炸裂）
- **节奏**：B1 快慢交替、B2 攻防转换（读肩/让过/借力，一句内完成）、B3 留白对峙、B4 连击终结
- **空间**：C1 高低差（Z 轴）、C2 包围与反包围、C3 距离控制、C4 地形互动（**破坏规模 = 烈度**）
- **力量体系**：D1 以弱胜强（过程感+代价感，惨胜）、D2 属性克制、D3 爆发三段（蓄力→升华→释放）、D4 形态变化、D5 等级层次（**用「能打到什么程度」展示**）
- **情绪与镜头**：E1 守护动机、E2 愤怒/冷静两极切换、E3 打斗台词、E4 胜负留白；F1 镜头转文字、F2 声音层次、F3 五感与陌生化比喻、F4 **旁观者反应（烈度计）**

### 10.2 表演 / 微表情模块

- **眼神 A**：视线落点（看眼=认真/看唇=心动/看手=克制/看地=逃避）、躲闪与追逐、眼部细节（红/亮/湿/垂）
- **面部 B**：嘴角（抿/勾/撇/颤）、眉头（皱/挑/舒展）、**脸红定位（耳尖→耳根→后颈，有顺序）**、呼吸（屏住/倒抽/长吐）、来不及收的表情
- **手部 C**：手指小动作、掌心温度、衣角袖口、触碰试探（碰一下弹开）
- **肢体 D**：距离感（半步进退/一拳距离）、姿态、停顿沉默、保护性动作
- **氛围 E**：留白、物件寄托、环境烘托（**离别写风/重逢写光**）
- **羁绊 F**：吐槽变关心、战斗默契、受伤第一反应、动作代宣言

> **每镜可见表情 1–3 个；情绪越重用笔越轻，用动作/细节替代「他很感动/难过」。**
>
> **「脸红定位」的适用边界**（与 [NSFW模式设计.md](./nsfw-design.md) §8.4 已对齐）：
> **视频提示词用定位式**（`耳尖→耳根→后颈`，写清扩散顺序），**小说正文禁脸红**。
> 禁的是笼统的 `blush` / `her cheeks flush`，不是精确的血流扩散描述。

### 10.3 特效模块

- 渲染规格：SSS、光追反射/折射、流体模拟、体积雾/God Ray、布料/发丝解算；硬光给角度/光比/色温/色值；**禁纯黑死影、过曝、平光**
- **火焰内部结构色**：`#FFF5E0 → #FFD23F → #FF6B1A → #8B2500`
- 分级：S 顶级（全要素+多点光+大规模交互）/ A 高级 / B 标准 / NONE
- **七项检查**：内部结构 / 点光 / 湍流 / 拖尾 / 环境交互 / 物理反馈 / 层次色

## 十一、风格系统（PART 4）

### 11.1 风格母版三层

1. **风格逻辑**：媒介与质感（真人实拍电影 / 3D 精品国漫 / 赛璐璐日漫 / 水墨 / 水彩）+ 影像气质 + 一句话母题
2. **整体色调**：主色/辅助色/点缀色、饱和度、冷暖关系、对比度
3. **整体光影**：主光来源/方向/软硬/色温、明暗对比、氛围光；**禁止平光、死黑、过曝、廉价滤镜**

### 11.2 题材母版库（示例）

| 题材 | 风格要点 |

| 喜剧群像 | 明亮通透、色彩明快；以「当前笑点人物」为焦点，反应拍与节奏停顿制造笑果 |

| 史诗战争 | 厚重油画质感；大地色系+金属冷光；体积雾、God Ray；军阵、摇臂一镜 |
| 恐怖创世 | 黑暗负空间+血肉微光；冷黑背景中以生物自发光为唯一光源 |
| 科幻末日 | 冷灰/青蓝+穿云暖光；破败材质、体积云、潮湿反射 |

## 十二、对本项目的适配判断

### 12.1 强烈建议照搬

| 项 | 理由 |
|---|---|
| **八条铁律**（R1–R8） | 整套文档的核心，尤其 R3（从事实重建）和 R8（不完整不出片） |
| **时长级联 9 条公式** | 填上我们方案的空缺 |
| **资产编号体系**（`SC-01`/`CH-01`/`PR-01` + 状态变体） | 我们完全没有 |
| **场景锚定图的俯视平面图** | 空间一致性的关键手段 |
| **风险打分 20 项** | 直接变校验器 |
| **反事实检验** | 揪出堆砌废话 |
| **规范镜头记录字段全集** | 直接当 `Shot` 模型定义 |
| **配置回显** | AUTO 判定必须显式告知用户 |
| **9 槽动作预算** `min(9, round(D×0.6))` | 防一镜塞太多动作 |
| **台词字数预算** `floor(D × 2.5)` | 有量化标准 |
| **多参考冲突裁决表** | 身份→脸图、服装→造型、动作→动作视频… |

### 12.2 需要改写再采纳

| 项 | 原资料 | 我们的做法 |
|---|---|---|
| **台词 vs 镜头时长方向** | 时长优先，台词塞进去 | **按入口区分**：从剧本进来 → 台词优先，提示加长/拆镜；从分镜设计进来 → 时长优先 |
| **单份 CSP 单模型** | 一次运行一个 `TARGET_VIDEO_MODEL` | 我们**同时输出多模型提示词**，用户选一个用 |
| **Phase A 内部执行** | 默认不输出 | 我们把 **CF 展示给用户看**（证据等级），这是产品差异点 |
| **`Arc Shot` 禁用** | MiniMax 禁环绕 | 与 `nsfw-template.md` 的 POV 运镜冲突，待实测；暂定为**慢速绕行允许、动作镜拆开** |
| **专业模块常驻** | 条件加载 | 同样的思路，但模块内容我们自己写（现在是 R18 向的） |

### 12.3 明确不做

| 项 | 理由 |
|---|---|
| Seedance / Kling / Vidu / Runway 适配器 | 目标模型只有 H3 |
| 军阵 / 史诗战争词汇 | 非主线 |
| R18 向的动作库 | 用户没要求 |
| PART 8 动作戏 A–G 全套 | 题材特定，需要时再补 |

### 12.4 待用户确认

1. **`TARGET_VIDEO_MODEL` 要不要做成多选题** —— 一次生成同时出 H3 + MiniMax 旧版两份提示词？
2. **CF 要不要给用户看** —— 带证据等级的规范事实台账，是产品亮点也是信息噪音
3. **俯视平面图要不要做** —— 它是场景一致性的关键，但要额外出一张图
4. **角色资产板用哪个模板** —— A（GPT_IMAGE）/ B（H3 六段）/ C（3D 国漫标签式），取决于我们的出图引擎
