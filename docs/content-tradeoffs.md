## 〇、先纠正一处

本鲸上一轮在 [冲突对照表.md](./conflict-register.md) 里没提内容层，是因为扫的全是**工程符号**（`task_type`、`Shot`、`Asset`）。主人问的是**提示词规则之间有没有打架**，这是两回事。

**有一个我差点报错的假冲突**：

| 口径 | 说法 | 出处 |
|---|---|---|
| A | 5 秒 0-1 句；15 秒 3-4 句 | `01_nsfw-template` 台词规则 |
| B | 15 秒 45/37 字 | `14_说明书` 速算表 |

**本鲸先以为是矛盾，算了一下发现不是。**

换算（每句约 10 字）：

| 时长 | 口径 A | 口径 B |
|---|---|---|
| 5 秒 | 0-1 句 | 12 字 ≈ 1.2 句 |
| 8 秒 | 1-2 句 | 20 字 ≈ 2 句 |
| 10 秒 | 2-3 句 | 25 字 ≈ 2.5 句 |
| 15 秒 | 3-4 句 | 37 字 ≈ 3.7 句 |

**基本吻合。** 一个是句数口径，一个是字数口径，说的是同一个上限。**不冲突，可以并存**（字数用于校验，句数用于设计）。

## 一、真正的内容层冲突：只有 3 处

扫完 15 份摘录，内容规则层面的**实质矛盾只有 3 处**，其余全是重复。

### 冲突 A · 节奏表 vs 首帧铁律（已解决，但文档没同步）

**问题**：

| 出处 | 5 秒节奏 |
|---|---|
| `01_nsfw-template` L139 | 铺垫 **0-1.5** → 转变 1.5-3 → 高潮 3-5 |
| `06_i2va-rules` L49 | 通用 0-1.5；**I2VA 覆盖为 0-0.5** |
| `07_hybrid-rules` L279 | 通用 0-1.5；**Hybrid 覆盖为 0-0.5** |
| `12_SKILL阶段E` L253 | **I2VA/Hybrid 改按 0-0.5** |

**这不叫冲突，叫「通用规则 + 分支覆盖」。** 三份资料口径一致。

**我们文档里的问题**（⚠️ **本条已更正 —— 本鲸初稿定位错了**）：

初稿写的是「`分镜系统规则.md` §四还把『0-1.5』当默认写」。**实测该文件全文没有 `0-1.5` 这个字符串**，§四 是时长级联九条公式，根本不涉及节奏表。

**实际情况是**：`分镜系统规则.md` **完全没有节奏表** —— 节奏规则只存在于 `H3提示词规则.md` §三（通用 0-1.5 + 首帧分支覆盖 0-0.5）。

**所以这不是「同步问题」，是「覆盖缺口」**：节奏表只在 1 份分册里有，另外三份都没引用它。整理时应把节奏表提到共用骨架，各分册只引用不复制。

### 冲突 B · 动作节奏：中速稳定 vs 由慢到快渐变

**这是唯一一个真正的矛盾。**

| 出处 | 说法 | 适用范围 |
|---|---|---|
| `01_nsfw-template` L395 | **实演类**：从中速起手，`a steady, even rhythm`，**禁** `slowly`/`gently`，也禁「由慢到快」渐变 | R18 实演动作 |
| `03_writing-conventions` §7 | 「用户要文字多一点 → **加细节与动作分解**」 | 通用写作 |
| `14_说明书` | 「转场须有动机」 | 通用 |

**看着不冲突？细看有问题：**

`01` 的实演类说「**禁止由慢到快的渐变结构**」，理由是「渐变是神情类的写法，不是动作节奏的写法」。

但 `08_戏剧性` / v9.0 的 PART 8 动作戏模块说：

> **B1 快慢交替**（短句连击 vs 长句慢蓄）

**一个说禁渐变，一个说要有快慢变化。**

**这确实矛盾**，但**不算真矛盾** —— 它们的对象不同：

| | 对象 | 理由 |
|---|---|---|
| `01` 禁渐变 | **R18 实演动作**（抽送等） | H3 天然倾向舒缓慢镜，不写节奏词会被拉慢；写渐变会变成机械抖动 |
| v9.0 要快慢 | **打斗动作** | 打斗需要节奏起伏 |

**结论**：不矛盾，是**题材分治**。但要写清楚「哪个题材用哪套」。

---

### 冲突 C · 台词设计：故事弧落点 vs 场景合理性

**这个是隐藏的，两份资料讲的其实是同一件事的两面，但优先级没说。**

| 出处 | 说法 |
|---|---|
| `01_nsfw-template` §九第 4 条 | 「台词要呼应故事弧」，给了**按弧类型**的台词模板（清纯→淫荡 说 X、淑女→黑化 说 Y） |
| `03_writing-conventions` §9 | 「台词必须符合场景」：时间/地点/在场者/物理条件决定音量与内容 |

**矛盾在哪**：

`01` 说「清纯→淫荡的弧，台词是她第一次主动开口求欢（"……想要吗？想不想进来？"）」
`03` 说「家里有睡着的父母 ⇒ 台词必须压低、短、断续」

**同一场戏，一个是模板化的勾引台词，一个是必须压低声的顾虑台词。**

**资料里没说哪个优先。**

**本鲸判断**：`03` 优先。理由是 `03` 是「被用户反复修正后固化」的约定，`01` 的弧台词模板只是示例。**场景约束是硬的，弧台词是软的。**

**但这条得写进文档明确优先级。**

## 三、NSFW 和 Tickle 要不要分开

这是主人问的重点。本鲸的答案是：**要分，但不是分成两个模式。**

### 3.1 先看清它们是什么关系

**Tickle 不是 NSFW 的子类，是「题材 × 玩法」的一个正交维度。**

看数据：

| 摘录 | 痒/搔痒 | 笑声 | 拟声 | R18 词 |
|---|---|---|---|---|
| `15_TK写作SKILL` | **114 次** | **81 次** | **65 次** | 少量 |
| `01_nsfw-template` | 0 | 1 | 0 | **112 次** |

**TK 那份的 R18 词很少，痒和笑声才是主体。** 它是一套「**感官刺激写作方法论**」，R18 只是它承载的题材之一。

### 3.2 它们各自管什么

| | NSFW（`01`/`02`） | TK（`15`） |
|---|---|---|
| **层级** | **内容策略**（露多少、尺度多大） | **表现手法**（怎么写出感官冲击） |
| **管什么** | L0-L5 档位、M1-M5 模块、8 类动作库 | 拟声词体系、笑声五阶段、符号系统 |
| **输出形态** | 视频提示词（英文正文 + `<d>` 台词） | **纯文本小说**（中文） |
| **适用面** | H3 视频 | AI 写作 |

### 3.3 关键判断：**它们的产出形态根本不同**

**NSFW 那套的终点是 H3 六段壳**（英文描述 + `<d>[Chinese]</d>` 台词），是给视频模型吃的。

**TK 那套的终点是中文小说正文**（`「」`『』` 对话 + 拟声词 + ❤ 符号），是给人读的。

**两套不能混，因为一个是 prompt，一个是 prose。**

### 3.4 所以怎么分

**本鲸建议：分成三个层次，不是两个模式。**

```
┌─────────────────────────────────────────┐
│  层三：题材包（可选，正交）                │
│  ├─ TK 调教（痒/笑声/拟声词）              │
│  ├─ 束缚 / 触手 / 机械（M3 题材元素）       │
│  └─ 其他玩法包                            │
│      ★ 每个包 = 一份词库 + 一份示例         │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  层二：内容策略（互斥）                    │
│  ├─ SFW                                   │
│  └─ NSFW：L0-L5 + M1-M5 + 8 类动作库      │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│  层一：共用骨架                            │
│  运镜 / 台词 / 声音 / 朝向 / 位移 / 质量门 │
└─────────────────────────────────────────┘
```

**关键：题材包和内容策略是两个维度**，可以组合：

- NSFW + TK 题材 = 有尺度的搔痒场景
- SFW + TK 题材 = 只有痒和笑，没有裸露
- NSFW + 无题材 = 通用性场景

### 3.5 但 TK 那份有个特殊问题

**它的产出是中文小说，不是提示词。** 而我们的 NSFW 层产出的是英文 prompt。

**所以 TK 包要放在「入口 C（Agent 对话生稿）」那一侧，不是渲染侧。**

也就是说：

| 用途 | 用哪套 |
|---|---|
| 写小说（入口 C） | TK 五阶段流水线 + TK 拟声词库 |
| 转提示词（渲染层） | NSFW 的 L0-L5 + 动作库 |
| **两者衔接** | 小说的 `[NSFW: 占位符]` → 提示词的动作库 |

**TK 那套的「占位符留白 → 专项填充」机制，正好是这个衔接点。**

### 3.6 结论

| 问题 | 答案 |
|---|---|
| NSFW 和 Tickle 要不要分开？ | **要分，但不在同一层** |
| 分成什么？ | NSFW 是**内容策略层**，TK 是**题材包 + 写作流水线** |
| 会冲突吗？ | **不会**，它们的产出形态不同（prompt vs prose） |
| 怎么组合？ | 题材包 × 内容策略 = 2×N 组合，正交 |

## 四、还有一个更大的取舍：**我们做不做「写小说」**

主人说过：

> 本质是 TXT 小说，只是加了一条工作流

**如果做入口 C（Agent 对话生稿），我们就等于内置了一套写作能力。**

这带来一个新问题：

| | 只做「文本 → 提示词」 | 加上「对话 → 文本 → 提示词」 |
|---|---|---|
| 定位 | **编译器** | **编剧 + 编译器** |
| 竞争者 | 分镜工具 | **写作工具 + 分镜工具** |
| 复杂度 | 中 | 高（多一套写作方法论 + 素材库） |
| TK 那套的价值 | 只有拟声词库有用 | **全套都有用** |

**本鲸的判断**：做。理由是主人已经提了两次「可以导入 TXT，也可以和 agent 沟通剧本」，而且 TK 那套证明这条路走得通。

**但要划清边界**：写作能力是**辅助**，不是主体。核心还是「文本 → 可靠指令」。

## 五、整理建议

### 5.1 内容规则的归并

按「**管什么**」归并，不按「出自哪份资料」：

| 归并到 | 内容 | 来源 |
|---|---|---|
| **base.md** 共用骨架 | 运镜六条、朝向 Facing、位移三要素、台词口型、音色表、技术排除行、枚举值 | `01` `04` `06` `07` `12` |
| **policy-sfw.md** | 通用表演描述、介质措辞、负面词 ①②③⑤⑥ | `02` `08` |
| **policy-nsfw.md** | L0-L5、M1-M5、8 类动作库、状态梯度、解剖术语、负面词+④ | `01` `02` `04` |
| **theme-*.md** 题材包 | TK（痒/笑/拟声）、束缚、触手… | `15` `01` M3 部分 |
| **writing-flow.md** 写作流水线 | 五阶段、占位符、知识库、素材库 | `15` |

### 5.2 三处真冲突的处理

| # | 冲突 | 处理 |
|---|---|---|
| A | 节奏表分支覆盖没同步 | 文档对齐（不改规则） |
| B | 动作节奏：禁渐变 vs 要快慢 | **按题材分治**：实演类中速稳定，打斗类快慢交替 |
| C | 台词：弧落点 vs 场景合理 | **场景优先**，弧台词作为内容方向参考 |

### 5.3 优先级

1. **先定 C**（台词优先级）—— 它影响每一句台词
2. 再定 B（动作节奏题材分治）
3. A 只是文档同步

## 六、给主人的话

**内容层的实际情况比工程层干净得多。**

工程层有 11 处冲突（3 个致命），因为它们涉及**代码结构**。

内容层只有 **3 处**，而且：
- 一处是文档没同步（A）
- 一处是题材分治没说清（B）
- 一处是优先级没定（C）

**剩下的全是重复，不是矛盾。**

所以整理的重头戏不在内容，在**工程结构**。

**NSFW 和 Tickle 分开的事**，本鲸的答案是：**分开，但分在不同层** —— NSFW 是内容策略，TK 是题材包 + 写作流水线，两者正交不冲突。
