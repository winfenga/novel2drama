## §3 NSFW 为什么提前 —— 本版最重要的排期改动

上一版把 NSFW 放在最后（第 12 个里程碑）。**这是错的**，原因不是"用户提过要 NSFW"，而是**三件 NSFW 相关的东西是架构级的，后置等于返工全表**：

| 事实 | 出处 | 后置的代价 |
|---|---|---|
| **策略层是拼装出来的**：`prompt = base.md + policy-{sfw\|nsfw}.md`，85% 共用、15% 分叉 | `CP` L161-176 | 若 SFW 先写死成一份完整 prompt，NSFW 来了要拆骨架 → base/shells/policy 全部重切 |
| **分叉粒度是 Shot 级，不是项目级** | `CP` L178-184 | 若 `contentPolicy` 后加，`Shot` schema 要改 → zod、DB、API、前端全部连带 |
| **合规闸门必须是硬编码拦截，不能是策略参数** | `CP` L176、`NSFW` L630-648 | 若当成开关后加，会做成可绕过 → 违反底线，且闸门要重做输入层双判定 |

**所以 NSFW 拆三段，分别放到三个位置：**

| 段 | 内容 | 落在 | 人日 | 为什么在这一格 |
|---|---|---|---:|---|
| **NSFW-P0** | 策略数据结构（L0–L5 / M1–M5 / 7×5 梯度 / `contentPolicy`）+ 合规闸门 + 策略拼装接口 | **M2（第 3 个里程碑）** | 7.0 | 全部是 schema 与输入层，与领域模型同时定，一次到位 |
| **NSFW-P1** | `policy-nsfw.md` 全文 + 8 类动作库 150+ 条目结构化 | **M3（与代码并行）** | 13.0 | 纯内容工程，不阻塞任何人，可与 M6 分镜引擎同时干 |
| **NSFW-P2** | 前端两套（theme + feature flags） | **M11（后置）** | 2.5 | 只改皮肤和开关，不动结构，确实可以等 |

依据：`NSFW` L610-627 明确「前端也做两套，但是复用，实际只有一些特性和贴图改变」——**结构不变，所以前端可以等；结构要变，所以 P0 不能等。**
